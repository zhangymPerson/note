## 0. 一页速览

- 面向个人使用，单机运行，不依赖云服务，不需要登录账号体系。
- 笔记内容为纯文本；提供新建、查看、编辑、删除、列表和模糊查询。
- 后端使用 Go，数据保存在本地 SQLite 单文件中。
- 前端为独立轻量工程（Vite + Svelte 5 + TypeScript，不使用 SvelteKit），构建产物直接输出到 Go 项目并通过 `//go:embed` 内嵌；运行时只分发 Go 二进制，不单独部署前端。Node/npm 仅用于开发和构建，目标机器无需安装。
- 支持「单向加密」的笔记：加密后数据库中永久只保存密文，不提供取消加密、密码找回或任何后门。
- 忘记密码时只能查看预先配置的密码提示问答；提示只用于帮助回忆，不能解密。密码遗忘后正文永久无法恢复。

## 1. 背景与目标

### 1.1 背景

个人日常记录碎片信息、临时想法和敏感事项时，希望有一个完全本地、可控、可长期使用的工具。现有云笔记依赖账号和网络，数据托管在第三方；通用笔记软件功能过重，且加密能力往往绑定到厂商的密钥体系。因此需要一个结构简单、数据自持、能够离线运行、并对少量敏感笔记提供强加密边界的小型应用。

### 1.2 产品目标

| 编号 | 目标 |
| --- | --- |
| G1 | 单机零外部依赖运行：一个 Go 二进制 + 一个 SQLite 文件即可使用。 |
| G2 | 记录成本低：打开页面到保存一条纯文本笔记不超过 3 次交互。 |
| G3 | 数据自持：所有数据只保存在本地磁盘，不上传、不联网同步。 |
| G4 | 加密无后门：加密笔记的正文不以明文写入数据库，密码遗失后任何人（包括应用本身）都无法恢复。 |
| G5 | 简单可用：页面朴素但完整，桌面和窄屏浏览器均可正常操作。 |

### 1.3 成功标准

- 第 9 节全部验收项通过。
- 加密操作完成后，在 SQLite 主库文件和 WAL 文件中检索不到该笔记的正文标记文本（验证方法见 9.1）。
- 在 10,000 条笔记、总计约 100 MB 文本的数据量下，列表与搜索满足 7.2 的性能指标。
- 构建产物为单个可执行文件：前端在构建阶段编译并内嵌，运行时不依赖 Node.js、npm 或外部网络资源。

## 2. 范围

### 2.1 MVP 范围

- 纯文本笔记的创建、查看、编辑、删除。
- 笔记列表，按更新时间倒序，分页展示。
- 标题与明文正文的模糊查询（子串匹配）。
- 笔记的不可逆加密、解锁查看、解锁后编辑。
- 密码提示问答（最多 3 组），仅用于辅助记忆。
- 忘记密码说明页，明确不提供恢复能力。
- 解锁会话的空闲自动锁定与手动锁定。
- 本地 SQLite 持久化、WAL、数据校验约束、基础安全响应头。
- 单二进制部署：独立前端工程在构建阶段产出并嵌入 Go 程序，不单独部署前端。

### 2.2 非目标（MVP 明确不做）

- 多用户、账号注册、角色权限、应用级登录口令。
- 云同步、多设备同步、分享链接、协作。
- 移动端原生应用、桌面客户端、浏览器插件。
- Markdown 渲染、富文本、图片、附件、语音、文件上传。
- 标签、文件夹、置顶、回收站、版本历史。
- 加密笔记正文的搜索、密码修改、取消加密、密码找回/重置、密钥托管。
- 笔记导入导出（加密或明文）。
- 国际化、主题系统、插件机制。
- 对外网暴露的安全加固（反向代理、TLS、公网认证）。

### 2.3 关键需求假设：「单向加密」的语义

本 PRD 将需求中的「单向加密」定义为：

1. **存储侧不可逆**：笔记一旦加密，数据库永久只保存密文；产品不提供「解密后以明文保存」或「取消加密」的操作。
2. **查看仍可解密**：持有正确密码时，应用在内存中解密并展示正文；这是查看，不是把明文重新落盘。
3. **无任何找回通道**：不存密码、不存可用于重置的密钥、不提供密保重置、不提供管理员后门。
4. **提示不等于凭据**：密码提示问答保存在明文中，只用于帮助用户回忆密码，不参与解密或密码校验。
5. **遗失即永久丢失**：密码遗失后，正文无法通过任何产品内手段恢复，只能删除或保留无用的密文。

> 如果实际期望是「连正确密码也不能查看的一次性封存」，则与本文假设不同，需要重新定义产品形态。该点列入第 13 节开放问题，开发前必须确认。

## 3. 用户与场景

### 3.1 目标用户

- 单个用户，在自己的电脑上运行应用。
- 具备基本的文件备份意识，理解「忘记密码即永久丢失」的风险。
- 主要在桌面浏览器使用，偶尔在窄屏下快速查看。

### 3.2 核心用户故事

| 编号 | 场景 |
| --- | --- |
| US-1 | 我打开应用，快速新建一条纯文本笔记并保存。 |
| US-2 | 我记得标题或正文里的一个词，通过搜索框找到相关笔记。 |
| US-3 | 我写了一条敏感笔记，希望它在数据库里是密文，并在查看时输入独立密码。 |
| US-4 | 我担心忘记密码，在加密时填写几个只有自己看得懂的提示问题。 |
| US-5 | 我忘记了密码，希望看到提示；如果确实想不起来，我接受正文永久丢失，并可以删除这条笔记。 |
| US-6 | 我在他人暂时使用我的电脑前，手动锁定已解锁的笔记；应用也会在空闲后自动锁定。 |
| US-7 | 我把 SQLite 文件复制到别处做备份；加密笔记在备份中仍然是密文。 |

## 4. 术语

| 术语 | 说明 |
| --- | --- |
| 明文笔记 | `is_encrypted = 0` 的笔记，正文以明文保存在 SQLite 中。 |
| 加密笔记 | `is_encrypted = 1` 的笔记，正文只以密文保存，标题仍为明文。 |
| 单向加密 | 指加密后存储不可逆、无密码找回通道；详见 2.3。 |
| 解锁 | 用户输入正确密码，应用在内存中解密正文并建立短时解锁会话。 |
| 锁定 | 清除内存中的解密密钥，使再次查看必须重新输入密码。 |
| 密码提示 | 加密时配置的问题和提示答案，明文保存，仅用于辅助回忆。 |
| KDF | 密钥派生函数，本产品使用 Argon2id 从密码派生加密密钥。 |
| AEAD | 带关联数据的认证加密，本产品使用 AES-256-GCM，可检测密码错误和密文篡改。 |

## 5. 功能需求

### 5.1 笔记管理

#### 5.1.1 字段定义

| 字段 | 规则 |
| --- | --- |
| 标题 | 必填；去除首尾空白后长度 1–200 个字符；明文保存，列表中展示。 |
| 正文 | 选填；纯文本 UTF-8；最大 1 MiB；保留原始换行与空白；不得包含 U+0000。 |
| 加密状态 | 明文或加密；加密后不可逆。 |
| 创建时间 | 服务端生成，UTC 存储，页面按本地时区展示。 |
| 更新时间 | 新建、编辑、加密、解锁后重新加密时更新。 |

#### 5.1.2 功能列表

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-1.1 | P0 | 新建明文笔记：输入标题与正文，保存后跳转到详情页。 |
| FR-1.2 | P0 | 查看明文笔记：正文以纯文本形式展示，保留换行，不解析 Markdown 或 HTML。 |
| FR-1.3 | P0 | 编辑明文笔记：修改标题和正文，保存后更新 `updated_at`。 |
| FR-1.4 | P0 | 删除笔记：二次确认后永久删除，MVP 不提供回收站。加密笔记的删除不要求输入密码。 |
| FR-1.5 | P0 | 列表：按 `updated_at` 倒序、每页 20 条展示，提供上一页/下一页。 |
| FR-1.6 | P0 | 校验失败时不丢失用户已输入内容，在原表单展示字段级错误。 |
| FR-1.7 | P0 | 前端默认转义（Svelte 文本插值），禁止 `{@html}`；正文使用 `white-space: pre-wrap` 展示。 |
| FR-1.8 | P1 | 编辑页离开前若有未保存修改，浏览器给出离开确认（渐进增强，不阻塞核心流程）。 |

### 5.2 模糊查询

查询为「包含式」子串匹配，不做拼音、纠错或分词。

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-2.1 | P0 | 在标题和**明文笔记正文**中做子串匹配，忽略 ASCII 大小写。 |
| FR-2.2 | P0 | 加密笔记只参与标题匹配；其正文不参与查询，结果中不展示正文摘要。 |
| FR-2.3 | P0 | 用户输入中的 `%`、`_`、`\` 必须按普通字符处理，不能作为 SQL 通配符。 |
| FR-2.4 | P0 | 空查询展示最近更新的笔记；查询无结果展示空状态和「新建笔记」入口。 |
| FR-2.5 | P0 | 标题命中的结果排在仅正文命中的结果之前，同一优先级按更新时间倒序。 |
| FR-2.6 | P0 | 查询词最大 200 个字符，超出部分不提交或返回校验提示；分页保留查询词。 |
| FR-2.7 | P1 | 明文笔记的结果可展示正文前 140 个字符的单行摘要；加密笔记不展示摘要。 |
| FR-2.8 | P1 | 搜索页固定提示：「加密笔记仅按标题匹配，正文不可搜索。」 |

### 5.3 加密笔记

#### 5.3.1 总原则

- 密码只用于派生密钥，**不保存密码本身，也不保存密码哈希或校验值**；密码是否正确由 AEAD 认证标签判定。
- 加密必须在一个数据库事务内完成：写入密文、清空正文字段、置位加密标记，防止出现半加密状态。
- 加密后正文列必须为 `NULL`；不允许保留明文副本。
- 不提供取消加密、修改密码、重置密码、导出明文等能力（MVP）。
- 标题、创建/更新时间、密码提示问答、加密状态属于明文元数据，这是设计取舍，必须在界面明确告知。
- 未解锁状态不返回正文；解密接口及包含正文的响应必须返回 `Cache-Control: no-store`。
- 应用重启后所有解锁会话失效。

#### 5.3.2 功能列表

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-3.1 | P0 | 新建笔记时可直接选择「加密保存」，填写密码与确认密码后创建为加密笔记。 |
| FR-3.2 | P0 | 明文笔记详情页提供「加密此笔记」入口，填写密码、确认密码和可选提示问答后执行加密。 |
| FR-3.3 | P0 | 加密前必须勾选确认项：「我已知晓：加密不可撤销，忘记密码后正文永久无法恢复。」未勾选则拒绝提交。 |
| FR-3.4 | P0 | 密码长度 8–256 个字符（UTF-8 编码不超过 1024 字节）；允许空格和任意 Unicode 字符；提交前统一做 NFC 规范化；不自动去除首尾空格。 |
| FR-3.5 | P0 | 密码提示最多 3 组；每组包含问题（≤100 字符）和提示答案（≤200 字符）；两项要么都填，要么都空。 |
| FR-3.6 | P0 | 已加密笔记在未解锁时展示标题、时间、提示问答入口和密码输入框，不展示正文。 |
| FR-3.7 | P0 | 输入正确密码后建立解锁会话，展示正文；错误密码统一提示「密码错误或数据损坏」，不区分具体原因。 |
| FR-3.8 | P0 | 解锁后可编辑加密笔记；保存时使用会话中的密钥重新加密（新随机 nonce），正文仍不落明文。 |
| FR-3.9 | P0 | 解锁会话空闲 10 分钟自动失效；页面提供「锁定」按钮；服务重启立即失效。 |
| FR-3.10 | P0 | 提供「忘记密码」说明页：展示提示问答、明确说明无法恢复、允许在不输入密码的情况下删除该笔记。 |
| FR-3.11 | P0 | 加密笔记的正文不进入搜索；搜索只能命中标题（见 5.2）。 |
| FR-3.12 | P0 | 明文笔记加密完成后，原明文数据应通过 `secure_delete` 与 WAL checkpoint 尽力清除（见 8.4.5）。 |
| FR-3.13 | P1 | 密码输入框提供显示/隐藏切换；不通过 URL、日志或埋点传递密码。 |
| FR-3.14 | P0 | 加密后密码与提示问答均不可修改（MVP）；如确需更换，只能新建笔记后重新录入。 |

#### 5.3.3 加密流程（用户视角）

1. 用户在新建页勾选「加密保存」，或在明文笔记详情页点击「加密此笔记」。
2. 填写密码、确认密码；可选填写最多 3 组提示问答。
3. 界面显示不可恢复警告，用户勾选确认项。
4. 提交后服务端完成 KDF 与加密，清空正文，返回「已加密」的详情页。
5. 之后每次查看正文，都需要输入密码解锁。

#### 5.3.4 解锁与查看流程

1. 打开加密笔记，页面只显示标题、时间和提示入口。
2. 输入密码并提交。
3. 密码正确：建立 10 分钟空闲有效的解锁会话，跳转到正文展示页。
4. 密码错误或密文损坏：统一错误提示，不消耗提示次数，不提供任何区分信息。
5. 用户可点击「锁定」主动清除该笔记的解锁状态；也可在页头「全部锁定」。

#### 5.3.5 忘记密码流程

1. 用户点击「忘记密码？」进入说明页。
2. 页面展示提示问答（若有），并说明提示不参与解密。
3. 页面明确告知：没有密码找回、重置或后门，正文将永久无法恢复。
4. 用户可以选择返回解锁页，或删除该笔记（删除不要求密码）。
5. 不存在任何「通过回答问题恢复」的路径。

#### 5.3.6 关键提示文案（必须出现在界面）

- 加密设置页：
  > 加密不可撤销。请自行妥善保管密码（建议使用密码管理器）。一旦遗忘，正文将永久无法恢复，本应用不提供任何找回或重置手段。
- 提示问答填写区：
  > 提示问答以明文保存在本地数据库中，仅用于帮助你回忆密码。请勿在提示中直接写出密码。
- 忘记密码页：
  > 本应用没有密码找回机制。提示问答不能解密笔记。如果密码确实遗忘，此笔记正文将永久无法恢复。

### 5.4 页面与接口清单

前端为独立 SPA 工程，页面路由由前端处理；Go 仅提供 `/api` JSON 接口和静态资源，并对非 API 的 GET 请求回退到 `index.html`。

**页面路由（前端 History 路由）**

| 路径 | 视图 |
| --- | --- |
| `/` | 笔记列表与搜索（`q`、`page` 查询参数） |
| `/notes/new` | 新建笔记 |
| `/notes/:id` | 明文详情；加密笔记未解锁时为解锁视图 |
| `/notes/:id/edit` | 编辑；加密笔记需已解锁 |
| `/notes/:id/encrypt` | 加密设置 |
| `/notes/:id/forgot` | 忘记密码说明 |

**API 路由（Go 提供 JSON）**

| 方法 | 路径 | 动作 |
| --- | --- | --- |
| GET | `/api/notes?q=&page=` | 列表与搜索 |
| POST | `/api/notes` | 创建笔记（可同时加密） |
| GET | `/api/notes/{id}` | 详情；加密未解锁时仅返回元数据与提示 |
| PUT | `/api/notes/{id}` | 更新笔记 |
| DELETE | `/api/notes/{id}` | 删除笔记 |
| POST | `/api/notes/{id}/encrypt` | 执行加密 |
| POST | `/api/notes/{id}/unlock` | 提交密码解锁 |
| POST | `/api/notes/{id}/lock` | 锁定单条笔记 |
| POST | `/api/lock` | 全部锁定 |
| GET | `/api/csrf` | 获取 CSRF Token 并写入 Cookie |
| GET | `/assets/*` | 前端构建产物 |
| GET | `/*` | 非 API 的 GET 回退到 `index.html` |

- 写操作使用 JSON 请求体，由前端 `fetch` 发起；不使用页面表单直发，也不做服务端重定向。
- 成功后的页面跳转由前端路由完成，避免整页刷新。
- API 不启用 CORS，仅允许同源访问；开发环境通过 Vite 代理保持同源。

## 6. 页面与交互

页面数量控制在 6 个主视图内，无弹窗式复杂交互。前端为独立轻量 SPA，使用 Vite + Svelte 5 + TypeScript，不使用 SvelteKit；不引入 UI 组件库、CSS 框架、路由库或状态管理库，路由使用自写微型 History 路由。

### 6.1 列表 / 搜索页

```
+------------------------------------------------------+
| 笔记                            [ 搜索词...... ] [搜] |
|                                        [ + 新建笔记 ] |
+------------------------------------------------------+
| 标题 A                                     2026-10-26 |
| 正文摘要（仅明文笔记）...                             |
+------------------------------------------------------+
| 已加密 · 标题 B                            2026-10-24 |
| （加密笔记不展示正文摘要）                            |
+------------------------------------------------------+
|                                    上一页  1/3  下一页 |
+------------------------------------------------------+
```

- 页头固定搜索框和「新建笔记」主按钮。
- 加密笔记显示「已加密」标识，不显示摘要。
- 搜索状态在结果上方展示「共 N 条结果」及清除搜索入口。
- 无数据、无结果分别有独立空状态。
- 搜索框自动聚焦；搜索词同步到 URL 查询参数后调用 API，不做实时搜索。

### 6.2 明文笔记详情

- 展示标题、更新时间、正文。
- 操作：编辑、加密此笔记、删除。
- 正文只读展示，保留换行；不渲染 HTML/Markdown。

### 6.3 加密笔记详情（未解锁）

- 展示标题、更新时间、「已加密」标识。
- 密码输入框、解锁按钮。
- 折叠的「查看密码提示」区域，展开后展示问题与提示答案。
- 「忘记密码？」链接。
- 不展示正文、摘要、字数或任何正文派生信息。

### 6.4 新建 / 编辑页

- 标题输入框、正文 `<textarea>`。
- 新建页提供可选的「加密保存」区域：密码、确认密码、提示问答、不可恢复确认项。
- 编辑加密笔记时不显示密码字段；依赖当前解锁会话，会话失效则跳回解锁页并提示。
- 明确「保存」「取消」；不做自动保存。

### 6.5 加密设置页

- 仅允许对明文笔记进入；对已加密笔记由 API 返回 409，前端跳转详情页。
- 密码、确认密码、最多 3 组提示问答。
- 提交按钮上方固定展示不可恢复警告，确认项为必选。
- 警示文案不可折叠、不可默认勾选。

### 6.6 忘记密码页

- 依次展示：提示问答（如有）、不可恢复说明、删除入口、返回解锁入口。
- 删除按钮需要二次确认；删除后回到列表。

### 6.7 反馈与异常状态

| 场景 | 交互 |
| --- | --- |
| 表单校验失败 | 原页面回显输入，字段下方显示具体错误；密码字段不回显原值。 |
| 创建/更新成功 | 前端路由跳转详情页；页头显示一次性成功提示。 |
| API 404 | 前端展示统一错误视图，提供返回列表链接。 |
| API 405/500 | 前端展示通用错误提示，不泄露内部细节。 |
| 未解锁访问编辑页 | 前端跳转到该笔记详情页（解锁视图），提示「请先解锁」。 |
| 会话过期后提交编辑 | API 返回 401，前端跳转解锁视图并提示「解锁已过期，请重新解锁」；已输入内容不保证保留。 |
| 删除确认 | 浏览器原生确认或页面内确认均可，文案包含「永久删除」。 |

### 6.8 可访问性与响应式

- 使用语义化 HTML、`label` 正确关联输入框，支持键盘完成全部操作。
- 窄屏（≥360px）单列布局，不出现横向滚动。
- 颜色对比满足基本可读性；不用颜色作为唯一状态提示。
- 核心流程由前端应用完成，要求启用 JavaScript；提供 `<noscript>` 提示。
- 路由切换后更新 `document.title`，并将焦点移动到主标题，保证读屏与键盘可用。

## 7. 非功能需求

### 7.1 安全与隐私

| 编号 | 要求 |
| --- | --- |
| NFR-S1 | 加密算法使用 AES-256-GCM；密钥由 Argon2id 从用户密码派生；每个笔记独立随机盐。 |
| NFR-S2 | 不保存密码、密码哈希或独立的密码校验值；错误密码由 GCM 认证失败识别。 |
| NFR-S3 | 密文使用随机 12 字节 nonce，并将笔记 ID 与格式版本作为 AAD，防止密文跨笔记移植。 |
| NFR-S4 | 加密、编辑重加密、删除后执行 WAL checkpoint；启用 `secure_delete`，减少明文残留。 |
| NFR-S5 | 应用默认仅监听 `127.0.0.1`；绑定非回环地址必须显式传入 `--allow-remote` 并打印风险警告。 |
| NFR-S6 | 所有写请求（POST/PUT/DELETE）校验 Origin/Sec-Fetch-Site，并使用双提交 CSRF Token；校验 Host，防 DNS Rebinding。 |
| NFR-S7 | 解密接口及所有动态 API 响应返回 `Cache-Control: no-store`；HTML 入口返回 `Referrer-Policy: no-referrer` 等安全头。 |
| NFR-S8 | 日志不得包含正文、密码、提示答案、完整查询串、Cookie 或表单内容。 |
| NFR-S9 | 不引用任何外部 CDN、字体、脚本或图片；前端构建产物全部通过 `go:embed` 内嵌到二进制。 |
| NFR-S10 | 数据库文件权限在 POSIX 下为 `0600`，数据目录为 `0700`（Windows 依赖用户账户隔离）。 |
| NFR-S11 | 前端不得将密码、解密正文或解锁密钥写入 `localStorage`、`sessionStorage` 或 IndexedDB，仅允许存在于当前页面内存。 |

### 7.2 性能

| 编号 | 指标 |
| --- | --- |
| NFR-P1 | 冷启动到可访问页面 ≤ 2 秒（常规 SSD）。 |
| NFR-P2 | 10,000 条笔记、约 100 MB 文本下，列表 API 服务端处理 ≤ 100 ms。 |
| NFR-P3 | 同等数据量下，搜索请求服务端处理 ≤ 300 ms。 |
| NFR-P4 | 解锁时的 KDF 预期耗时 100–500 ms，属于安全成本，不视为性能缺陷。 |
| NFR-P5 | 单次解密 1 MiB 正文 ≤ 50 ms。 |
| NFR-P6 | 常驻内存通常 < 100 MB；KDF 峰值增加约 64 MB。 |
| NFR-P7 | 同一时刻最多执行 1 个 KDF 计算，避免并发解锁导致内存峰值叠加。 |
| NFR-P8 | 前端首屏 JS/CSS（gzip）≤ 150 KB；不使用大图、Web 字体和动画库。 |

### 7.3 兼容与部署

- Go 1.26 及以上；使用标准库 `net/http` 方法路由。
- Node.js 22 LTS 及以上（建议 24 LTS）仅用于前端开发和构建；运行机不需要 Node/npm。
- 前端为独立工程 `web/`（Vite + Svelte 5 + TypeScript，不使用 SvelteKit）；Vite 构建输出到 `internal/web/dist`，由 `//go:embed` 内嵌。
- SQLite 驱动使用纯 Go 实现（`modernc.org/sqlite`），`CGO_ENABLED=0` 可构建。
- 支持 Windows 10/11、macOS、Linux（amd64/arm64）。
- 浏览器：最近两个大版本的 Chrome、Edge、Firefox、Safari，且必须启用 JavaScript。
- 构建产物为单个二进制；不单独部署前端，不分发 `node_modules`。
- SPA 使用 History 路由；Go 对非 API 的 GET 请求回退 `index.html`。

### 7.4 可靠性

- 所有多步写操作使用事务；加密操作必须原子完成。
- 崩溃后数据库应保持可打开、可恢复状态（WAL 模式）。
- 启动时执行 schema 迁移并校验数据库完整性；失败时拒绝启动并输出明确错误。
- 支持 SIGINT/SIGTERM 优雅退出，关闭前执行 WAL checkpoint。
- 文件损坏时应用不得尝试静默重建数据；应保留原文件并提示用户从备份恢复。

### 7.5 可维护性

- 依赖数量保持最小；后端不使用 Web 框架、ORM；前端不引入 UI 组件库、CSS 框架、路由库、状态管理库，使用 Svelte 内置能力。
- 前端提交 `package-lock.json`，构建统一使用 `npm ci`；Node 版本通过 `.nvmrc`/`engines` 固定。
- 前后端通过 `/api` JSON 契约交互；API 客户端集中管理，不在组件中散落请求逻辑。
- 加密参数、格式版本作为常量集中管理，并在密文中可追溯。
- 核心模块（加密、存储、HTTP 处理器、前端 API 客户端）具备单元测试或集成测试。
- 数据库结构变更通过带版本号的迁移脚本完成。

### 7.6 威胁模型

| 威胁 | 是否防护 | 说明 |
| --- | --- | --- |
| 数据库文件被复制、误发或随备份泄露 | 部分 | 正文为密文；标题、提示、时间、数量仍为明文。弱密码可被离线爆破。 |
| 磁盘被离线读取 | 部分 | 同上，安全性取决于密码强度与 Argon2id 成本。 |
| 同机其他用户直接操作正在运行的应用 | 否 | MVP 无应用级登录；依赖操作系统账户隔离。 |
| 键盘记录、屏幕截图、内存抓取 | 否 | 任何本地明文展示工具都无法防御。 |
| 浏览器前进/后退缓存短暂显示已锁定内容 | 部分 | 使用 `no-store`；不保证浏览器进程内存被立即清除。 |
| 恶意站点跨站发起写请求 | 是 | Origin 校验 + CSRF Token + SameSite Cookie + JSON Content-Type。 |
| 存储型 XSS（标题/正文注入脚本） | 是 | Svelte 默认文本转义，禁止 `{@html}`；CSP 限制脚本来源。 |

| SSD 物理层残留旧明文 | 否 | 超出应用层能力；应用只保证逻辑删除与 WAL 清理。 |

### 8.3 数据模型

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA secure_delete = ON;
PRAGMA busy_timeout = 5000;

CREATE TABLE IF NOT EXISTS notes (
    id           TEXT PRIMARY KEY,              -- UUID v4
    title        TEXT NOT NULL,                 -- 明文标题
    content      TEXT,                          -- 明文正文；加密后必须为 NULL
    is_encrypted INTEGER NOT NULL DEFAULT 0 CHECK (is_encrypted IN (0, 1)),
    cipher       BLOB,                          -- nonce(12) || ciphertext || tag
    kdf_salt     BLOB,                          -- 16 字节随机盐
    kdf_params   TEXT,                          -- JSON，见 8.4.1
    hints        TEXT,                          -- JSON 数组，明文提示问答
    created_at   TEXT NOT NULL,                 -- RFC3339 UTC
    updated_at   TEXT NOT NULL,
    CHECK (
        (is_encrypted = 0
            AND content IS NOT NULL
            AND cipher IS NULL
            AND kdf_salt IS NULL
            AND kdf_params IS NULL
            AND hints IS NULL)
        OR
        (is_encrypted = 1
            AND content IS NULL
            AND cipher IS NOT NULL
            AND kdf_salt IS NOT NULL
            AND kdf_params IS NOT NULL)
    )
);

CREATE INDEX IF NOT EXISTS idx_notes_updated_at
    ON notes(updated_at DESC);
```

- `hints` 示例：`[{"q":"我最喜欢的城市？","a":"第一次独自旅行去的地方"}]`；无提示时为 `NULL`。
- 迁移使用 `PRAGMA user_version` 记录版本，启动时按序执行并置于事务内。
- 搜索规模较小时依赖 `updated_at` 索引与全表扫描；数据量增长后再评估 FTS5。
- 单连接写入或短事务写入；WAL 允许读并发，个人场景足够。

### 8.4 加密设计

#### 8.4.1 参数

| 项目 | 值 |
| --- | --- |
| KDF | Argon2id，version 19 |
| 内存 | 64 MiB（65536 KiB） |
| 迭代次数 | 3 |
| 并行度 | 2 |
| 派生密钥长度 | 32 字节 |
| 盐 | 每条笔记在设置密码时生成 16 字节随机值；编辑重加密沿用 |
| AEAD | AES-256-GCM，12 字节随机 nonce |
| AAD | `note:v1:` + 笔记 ID 的字节串 |
| 密文存储 | `nonce || AES-GCM 输出（含 16 字节 tag）` |
| 密码规范化 | NFC |

`kdf_params` 示例：

```json
{"algo":"argon2id","version":19,"time":3,"memory":65536,"threads":2,"keylen":32}
```

读取时必须校验参数边界：`time ∈ [1,10]`、`memory ∈ [8192,262144] KiB`、`threads ∈ [1,8]`、`keylen = 32`、`algo = argon2id`。超出范围视为数据损坏并拒绝解密，防止被篡改的数据库参数导致内存耗尽。

#### 8.4.2 加密伪代码

```text
salt   = random(16)   -- 设置密码时生成；编辑重加密沿用
key    = Argon2id(NFC(password), salt, time=3, memory=65536, threads=2, len=32)
nonce  = random(12)
aad    = []byte("note:v1:" + noteID)
cipher = nonce || AESGCM(key).Seal(nil, nonce, []byte(content), aad)

BEGIN TRANSACTION
  UPDATE notes
     SET cipher = :cipher,
         kdf_salt = :salt,
         kdf_params = :params,
         hints = :hints,
         content = NULL,
         is_encrypted = 1,
         updated_at = :now
   WHERE id = :noteID AND is_encrypted = 0
COMMIT

wal_checkpoint(TRUNCATE)   -- 尽力清除 WAL 中的旧明文
zeroize(key)
```

- 若 UPDATE 影响 0 行，说明笔记已加密或不存在，返回 409/404。
- 事务失败时不得修改任何字段，明文保持不变。
- 新笔记直接加密时，在同一事务内插入密文记录，正文不写库。

#### 8.4.3 解密伪代码

```text
row = SELECT cipher, kdf_salt, kdf_params FROM notes WHERE id = :noteID
if row.is_encrypted != 1: error
params = parse_and_validate(row.kdf_params)
key    = Argon2id(NFC(password), row.kdf_salt, params)
nonce  = row.cipher[0:12]
plain, err = AESGCM(key).Open(nil, nonce, row.cipher[12:], aad)
if err: return generic_error("密码错误或数据损坏")
return plain
```

- 解密成功后把 `key` 放入解锁会话；不把密码或明文写入会话。
- 解密失败不得区分「密码错误」「nonce 有问题」「tag 不匹配」。
- 明文只在 Go 请求处理期间和浏览器内存中存在；API 响应不得写入浏览器持久化存储。

#### 8.4.4 编辑重加密

- 仅在有效解锁会话下允许。
- 使用会话中的 32 字节密钥，生成新的 12 字节 nonce，重新加密新正文，更新 `cipher` 与 `updated_at`。
- 盐与 KDF 参数不变；不修改密码。
- 正文列仍为 `NULL`，编辑过程不产生明文落盘。
- 保存后建议在响应前清除请求中的明文字节切片（尽力而为，Go 无法保证 GC 彻底擦除）。

#### 8.4.5 明文残留处理

- 全局启用 `PRAGMA secure_delete = ON`，删除/覆盖的页内容以零填充。
- 加密或删除事务提交后执行 `PRAGMA wal_checkpoint(TRUNCATE)`，截断 WAL 中的旧页。
- 关闭应用时再次 checkpoint。
- 定期维护（可选、手动）执行 `VACUUM` 重写数据库文件；MVP 不自动对大数据量执行。
- 明确边界：备份文件、文件系统快照、SSD 磨损均衡层可能保留旧数据，应用无法保证物理擦除。

#### 8.4.6 为什么没有密码校验哈希

独立保存密码哈希会额外提供离线爆破目标，且与 AEAD 的认证能力重复。直接让 GCM tag 校验密码，可以在不增加泄露面的情况下判断密码是否正确。代价是每次校验都必须完整执行 KDF 和解密，这对本产品可接受。

### 8.5 解锁会话

- 密钥存储位置：仅进程内存，不写入 SQLite、日志或 Cookie；Cookie 只保存随机会话标识。
- 会话标识：32 字节随机 token，十六进制编码后放入 Cookie `note_sess`。
- Cookie 属性：`HttpOnly`、`SameSite=Strict`、`Path=/`；本地 HTTP 下不设 `Secure`，如经 TLS 反向代理则应启用。
- 会话内容：`token -> { noteID -> 32 字节密钥, expiresAt }`。
- 有效期：10 分钟空闲过期；每次成功访问该笔记正文时刷新到期时间。
- 手动锁定：单条锁定删除对应密钥；全部锁定删除整个会话并清除 Cookie。
- 清理：后台定时清理过期会话；服务重启、优雅关闭时全部清零。
- 并发：同一时刻最多一个 KDF 计算（信号量），避免内存峰值。
- 会话 Cookie 使用浏览器会话级 Cookie，关闭浏览器后自然失效。
- 边界：锁定只影响后续请求，已经显示在屏幕上的正文无法被应用远程擦除；锁屏前应关闭或刷新页面。

### 8.6 HTTP 与 API 约定

| 场景 | 状态码 | 响应 |
| --- | --- | --- |
| 创建成功 | 201 | 新笔记 JSON |
| 读取/更新/加密/解锁/锁定成功 | 200 | 对应 JSON |
| 删除成功 | 204 | 无响应体 |
| 参数校验失败 | 400 | `{"error":{"code":"validation_failed","message":"...","fields":{...}}}` |
| 未解锁或解锁过期 | 401 | `code=unlock_required` |
| 密码错误或密文损坏 | 401 | `code=decrypt_failed`，统一文案 |
| CSRF/Origin 校验失败 | 403 | 通用错误 |
| Host 校验失败 | 400 | 通用错误 |
| 未找到笔记 | 404 | 通用错误 |
| 方法不允许 | 405 | 通用错误 |
| 笔记已加密仍请求加密 | 409 | `code=already_encrypted` |
| 请求体超限 | 413 | 通用错误 |
| 写请求不是 JSON | 415 | 通用错误 |
| 内部错误 | 500 | 通用错误，不返回堆栈 |

- POST/PUT 请求使用 `application/json; charset=utf-8`，请求体上限 2 MiB；DELETE 允许空请求体，但同样需要 CSRF 头。
- 除 204 外，所有 API 响应使用 `Content-Type: application/json; charset=utf-8`，并返回 `Cache-Control: no-store`。
- 成功不返回 303；页面导航由前端路由完成。
- 错误响应统一为 `{"error":{"code":"...","message":"...","fields":{...}}}`；`message` 可直接展示，不得包含内部细节。
- CSRF：`GET /api/csrf` 返回 Token 并写入 `HttpOnly`、`SameSite=Strict` 的 Cookie；写请求在 `X-CSRF-Token` 头携带同一 Token，服务端同时校验头、Cookie、Origin/Sec-Fetch-Site。
- POST/PUT 写请求强制 JSON Content-Type；浏览器原生跨站表单无法直接构造该请求，降低 CSRF 面。
- API 不启用 CORS，不返回 `Access-Control-Allow-*`；Vite 开发服务器通过代理将 `/api` 转发到 Go，生产由 Go 同源提供页面与 API。
- SPA 回退仅处理无扩展名或 `Accept: text/html` 的 GET 请求；`/api/*` 与 `/assets/*` 不参与回退。
- 获取加密笔记详情时，未解锁只返回标题、时间、提示与 `is_encrypted`；解锁后的同一接口才返回 `content`，并以 `unlocked` 标记。
- 标题去首尾空白后校验；正文不去空白、不做 HTML 转义存储，由前端以文本节点渲染。

### 8.7 搜索实现

```sql
-- :pattern = "%" || escaped(q) || "%"，escaped 将 \ % _ 转义
SELECT id, title, is_encrypted,
       CASE WHEN is_encrypted = 0 THEN substr(content, 1, 140) END AS snippet,
       updated_at
  FROM notes
 WHERE title LIKE :pattern ESCAPE '\'
    OR (is_encrypted = 0 AND content LIKE :pattern ESCAPE '\')
 ORDER BY CASE WHEN title LIKE :pattern ESCAPE '\' THEN 0 ELSE 1 END,
          updated_at DESC,
          id DESC
 LIMIT 20 OFFSET :offset;
```

- 转义顺序：先将 `\` 替换为 `\\`，再将 `%` 替换为 `\%`、`_` 替换为 `\_`。
- SQLite `LIKE` 默认对 ASCII 大小写不敏感，对非 ASCII 为精确子串；满足中文搜索需求。
- 分页总数使用同条件的 `COUNT(*)` 查询。
- 加密笔记正文为 `NULL`，条件中显式排除，避免未来实现误查。
- 摘要将换行折叠为空格；前端以文本节点渲染，Svelte 默认转义，禁止 `{@html}`。
- 搜索词通过 GET 参数传递，会出现在浏览器地址栏与历史记录中；这是本地单用户场景下的有意的简单取舍，服务端日志仍不记录查询串。
- 性能不足时的演进方向：SQLite FTS5 `trigram` 索引，仅索引明文笔记。

### 8.8 安全中间件

按顺序执行：

1. **请求恢复**：捕获 panic，记录不含敏感数据的堆栈摘要，返回 500。
2. **Host 校验**：默认允许 `127.0.0.1`、`localhost`、`[::1]` 及配置端口；显式启用 `--allow-remote` 时，额外允许配置的监听主机；其他 Host 返回 400。
3. **安全响应头**：
   - `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; form-action 'self'; frame-ancestors 'none'; base-uri 'none'`
   - `X-Content-Type-Options: nosniff`
   - `X-Frame-Options: DENY`
   - `Referrer-Policy: no-referrer`
   - API 与 HTML 入口使用 `Cache-Control: no-store`；带内容哈希的 `/assets/*` 使用 `public, max-age=31536000, immutable`
   - CSP 对生产构建生效；开发模式由 Vite 提供页面，不强制该策略
4. **CSRF**：`GET /api/csrf` 签发随机 Token Cookie；写请求同时校验 `X-CSRF-Token` 头、Cookie、Origin/Sec-Fetch-Site。
5. **访问日志**：记录方法、路由模式、状态码、耗时、响应字节数；不记录查询串、请求体、Cookie、密码或正文。
6. **超时**：`ReadHeaderTimeout=5s`、`ReadTimeout=15s`、`WriteTimeout=30s`、`IdleTimeout=60s`。

### 8.9 配置与运行

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--addr` | `127.0.0.1:8080` | 监听地址 |
| `--db` | `./data/notes.db` | SQLite 文件路径 |
| `--allow-remote` | 关闭 | 显式允许绑定非回环地址，并打印风险警告 |

开发模式（两个终端）：

```bash
# 终端 1：Go API 与内嵌页面（需已构建过 dist）
go run ./cmd/note

# 终端 2：Vite 开发服务器，/api 代理到 127.0.0.1:8080
cd web && npm ci && npm run dev
```

构建与发布：

```bash
# 前端产物直接写入 Go 项目
cd web && npm ci && npm run build
cd ..

# 编译单二进制，前端已内嵌
CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o note ./cmd/note
```

`web/vite.config.ts` 关键配置：

```ts
import { defineConfig } from 'vite'
import { svelte } from '@sveltejs/vite-plugin-svelte'

export default defineConfig({
  plugins: [svelte()],
  build: {
    outDir: '../internal/web/dist',
    emptyOutDir: true,
  },
  server: {
    proxy: {
      '/api': {
        target: 'http://127.0.0.1:8080',
        changeOrigin: true,
      },
    },
  },
})
```

- 使用 `@sveltejs/vite-plugin-svelte` 编译 Svelte，`svelte.config.js` 启用 `vitePreprocess()` 处理 TypeScript；不引入 SvelteKit、SSR/SSG 或文件路由。
- 发布统一使用 `just build`，固定执行「前端构建 → Go 编译」，避免产物不同步。
- `internal/web/dist` 为生成物，不提交版本库；未生成时 `go build` 会因 `//go:embed` 找不到文件而失败，属于预期的构建保护。
- 首次进入开发或拉取新代码后，先执行一次 `cd web && npm ci && npm run build`，再启动 Go；之后前端改动由 Vite 开发服务器负责，无需反复构建 dist。
- `changeOrigin: true` 保证代理后的 Host 为 `127.0.0.1:8080`，通过 Go 的 Host 白名单校验。
- 开发代理还必须把 Origin 重写为 `http://127.0.0.1:8080`；否则浏览器 Origin 与代理后的 Host 不一致，写请求会被 Origin 校验拒绝（完整配置见技术方案 10.1）。
- Node/npm 只存在于构建机和开发机；部署机只需要二进制和数据目录。
- 启动流程：解析参数 → 创建数据目录（权限 0700）→ 打开数据库并设置 PRAGMA → 执行迁移 → 校验 schema → 装配 API、静态资源与 SPA 回退 → 监听。失败时输出明确错误并以非零码退出。

### 8.10 日志

- 输出到 stdout，格式为结构化单行文本或 JSON。
- 字段：时间、级别、方法、路由模式、状态码、耗时、响应大小。
- 禁止字段：请求体、密码、提示答案、笔记正文、查询词、Cookie、Authorization。
- 解密/加密失败只记录笔记 ID 与错误类别（如 `decrypt_failed`），不记录输入。
- 启动时记录数据库路径（不含敏感信息）。

### 8.11 备份与数据迁移

- 备份对象：`notes.db` 及可能存在的 `notes.db-wal`、`notes.db-shm`；推荐先停止应用，或使用 `sqlite3 notes.db ".backup 'backup.db'"`。
- 加密笔记在备份中保持密文；明文笔记在备份中仍是明文，需由用户自行保护备份。
- 备份可能包含加密前的历史明文（例如旧备份），应用无法追溯清理。
- 迁移：复制整个数据目录到新机器，保持文件权限；应用启动时执行 schema 迁移，不改变已有密文。

### 8.12 前端工程约束

- 目录 `web/` 为独立工程：Vite + Svelte 5 + TypeScript；TypeScript 开启 `strict`；不使用 SvelteKit。
- 不引入 UI 组件库、CSS 框架、路由库、状态管理库、SSR/SSG 框架；组件和样式手写。
- 使用 Svelte 内置 scoped CSS 与少量全局 CSS；状态使用 Svelte 5 runes 或内置 stores，不引入额外状态库。
- 路由使用自写微型 History 路由（约 60 行），Go 负责回退 `index.html`，未知 API 仍返回 JSON 404。
- API 访问集中在 `src/api/`，统一处理错误码、CSRF Token 和 401 解锁跳转；不在组件内散落 `fetch`。
- 禁止 `{@html}`；标题、正文、摘要、提示问答只通过 `{...}` 文本插值渲染。
- 密码、解密正文和解锁密钥不得写入 `localStorage`、`sessionStorage` 或 IndexedDB；解锁态由服务端 Cookie 会话维持，前端只在内存中保留当前视图状态。
- 页面刷新后允许重新请求已解锁内容（依赖服务端会话 Cookie）；锁定后前端不得保留正文缓存。
- 构建使用 `npm ci` 与提交的 `package-lock.json`；Node 版本固定为 22 LTS 及以上（建议 24 LTS，`.nvmrc`/`engines`）。
- 类型检查使用 `svelte-check --tsconfig ./tsconfig.json`；关键 API 客户端、路由匹配与工具函数使用 Vitest + `@testing-library/svelte` 测试。
- 初始加载的 JS/CSS 目标 ≤ 150 KB（gzip），不使用大图、Web 字体和动画库。

### 9.2 验证明文残留的具体方法

1. 创建包含唯一标记 `PLAINTEXT_MARKER_20261026` 的笔记。
2. 执行加密。
3. 关闭应用或触发 checkpoint。
4. 对 `data/notes.db`、`data/notes.db-wal` 执行：

   ```bash
   grep -a "PLAINTEXT_MARKER_20261026" data/notes.db data/notes.db-wal
   ```

5. 预期：无匹配。若匹配到旧备份或文件系统快照，不属于运行时数据库泄漏，但需在文档中提示用户。

## 12. 风险与缓解

| 编号 | 风险 | 影响 | 缓解措施 |
| --- | --- | --- | --- |
| R1 | 用户忘记密码，正文永久丢失 | 高 | 强制确认项；加密时推荐使用密码管理器；提示问答；文档反复说明；默认不加密。 |
| R2 | 提示问答泄露线索 | 中 | 提示明文保存并明确告知；建议不使用密码原文；限制条数与长度。 |
| R3 | 标题、时间、提示仍为明文 | 中 | 明示元数据边界；后续版本可评估标题加密（会牺牲列表搜索）。 |
| R4 | 弱密码被离线爆破 | 高 | Argon2id 64 MiB；最低 8 个字符并推荐 12 个字符以上或口令短语；不夸大安全承诺。 |
| R5 | WAL、备份、快照中残留旧明文 | 中 | `secure_delete`、加密后 checkpoint、退出 checkpoint、文档说明备份边界。 |
| R6 | LIKE 全表扫描在超大数据量下变慢 | 中 | 限制单条大小；设定 10k/100 MB 指标；后续引入 FTS5 trigram。 |
| R7 | 解锁期间内存或屏幕泄露 | 中 | 短会话、手动锁定、`no-store`；明确无法防御本机恶意程序。 |
| R8 | 应用被暴露到公网 | 高 | 默认回环监听；`--allow-remote` 显式开启并警告；MVP 不提供公网认证。 |

| R10 | 前端产物与 Go 二进制不同步，或忘记构建 | 中 | 统一使用 `just build`；从干净目录构建；`dist` 不提交；embed 缺失时构建失败；发布前执行 AC-25。 |

## 附录 B：安全自检清单
