## 0. 一页速览

- 面向个人使用，单机运行，不依赖云服务，不需要登录账号体系。
- 笔记正文保存原始 Markdown 文本；提供新建、查看、编辑、删除、列表、模糊查询和可选分类。
- 后端使用 Go，数据保存在本地 SQLite 单文件中。
- 前端为独立轻量工程（Vite + Svelte 5 + TypeScript，不使用 SvelteKit），构建产物直接输出到 Go 项目并通过 `//go:embed` 内嵌；运行时只分发 Go 二进制，不单独部署前端。Node/npm 仅用于开发和构建，目标机器无需安装。
- 支持「单向加密」的笔记：加密在浏览器内完成（WebCrypto），数据库里永久只保存密文字节，不提供取消加密、密码找回或任何后门。
- 全局主密码在引导页第二步配置，配一条助记问题作提示；提示不能解密，也不参与校验。
- 主密码可以修改：旧密码在浏览器里靠试解已有密文来验证，随后逐条重加密全部加密笔记。**仍然没有找回**——服务端任何时候都不具备验证口令的能力。
- 顶栏用户名进入信息页：展示运行环境与构建版本（含 git hash、构建日期），并在这里改用户名、助记问题与主密码。

## 1. 背景与目标

### 1.1 背景

个人日常记录碎片信息、临时想法和敏感事项时，希望有一个完全本地、可控、可长期使用的工具。现有云笔记依赖账号和网络，数据托管在第三方；通用笔记软件功能过重，且加密能力往往绑定到厂商的密钥体系。因此需要一个结构简单、数据自持、能够离线运行、并对少量敏感笔记提供强加密边界的小型应用。

### 1.2 产品目标

| 编号 | 目标                                                                                       |
| ---- | ------------------------------------------------------------------------------------------ |
| G1   | 单机零外部依赖运行：一个 Go 二进制 + 一个 SQLite 文件即可使用。                            |
| G2   | 记录成本低：打开页面到保存一条纯文本笔记不超过 3 次交互。                                  |
| G3   | 数据自持：所有数据只保存在本地磁盘，不上传、不联网同步。                                   |
| G4   | 加密无后门：加密笔记的正文不以明文写入数据库，密码遗失后任何人（包括应用本身）都无法恢复。 |
| G5   | 简单可用：页面朴素但完整，桌面和窄屏浏览器均可正常操作。                                   |

### 1.3 成功标准

- 第 9 节全部验收项通过。
- 加密操作完成后，在 SQLite 主库文件和 WAL 文件中检索不到该笔记的正文标记文本（验证方法见 9.1）。
- 在 10,000 条笔记、总计约 100 MB 文本的数据量下，列表与搜索满足 7.2 的性能指标。
- 构建产物为单个可执行文件：前端在构建阶段编译并内嵌，运行时不依赖 Node.js、npm 或外部网络资源。

## 2. 范围

### 2.1 MVP 范围

- 纯文本笔记的创建、查看、编辑、删除。
- 笔记列表，按更新时间倒序，分页展示。
- 标题与明文正文的模糊查询（子串匹配）。
- 笔记的不可逆加密（浏览器端加解密）、解锁查看、解锁后编辑。
- 全局主密码的配置与修改（修改需旧密码）、助记问题（单条问题文本，仅用于辅助记忆，可随时单独修改）。
- 用户信息页 `/info`：运行环境与构建版本只读展示 + 用户名/主密码/助记问题修改 + 迁移状态。
- 忘记密码说明页，明确不提供恢复能力。
- 手动锁定与刷新即失效的解锁状态（密钥只活在页面内存）。
- 本地 SQLite 持久化、WAL、数据校验约束、基础安全响应头。
- 单二进制部署：独立前端工程在构建阶段产出并嵌入 Go 程序，不单独部署前端。

### 2.2 非目标（MVP 明确不做）

- 多用户、账号注册、角色权限、应用级登录口令。
- 云同步、多设备同步、分享链接、协作。
- 移动端原生应用、桌面客户端、浏览器插件。
- 富文本编辑器、图片、附件、语音、文件上传。（Markdown 渲染自 v1.3 起纳入范围，见 5.1.2 FR-1.2）
- 标签、置顶、版本历史。（分类自 v1.3、回收站自 v1.7 起纳入范围，见 5.5 与 5.1.2 FR-1.4）
- 加密笔记正文的搜索、取消加密、密码找回/重置、密钥托管。修改主密码自 v1.4 起纳入范围（见 2.5），但它要求知道旧密码，与找回是两件事。
- 笔记导入导出（加密或明文）。
- 国际化、主题系统、插件机制。
- 对外网暴露的安全加固（反向代理、TLS、公网认证）。

### 2.3 关键需求假设：「单向加密」的语义

本 PRD 将需求中的「单向加密」定义为：

1. **存储侧不可逆**：笔记一旦加密，数据库永久只保存密文；产品不提供「解密后以明文保存」或「取消加密」的操作。
2. **查看仍可解密**：持有正确密码时，应用在内存中解密并展示正文；这是查看，不是把明文重新落盘。
3. **无任何找回通道**：不存密码、不存可用于重置的密钥、不提供密保重置、不提供管理员后门。
4. **提示不等于凭据**：助记问题以明文保存在本地，只用于帮助用户回忆主密码，不参与解密或密码校验；系统不保存答案。
5. **遗失即永久丢失**：密码遗失后，正文无法通过任何产品内手段恢复，只能删除或保留无用的密文。修改密码不算恢复——它要求先提供旧密码。

> 如果实际期望是「连正确密码也不能查看的一次性封存」，则与本文假设不同，需要重新定义产品形态。该点列入第 13 节开放问题，开发前必须确认。

### 2.4 v1.3 实现偏离

实现阶段的评审结论把下列六项从 v1.2 原案改为现在的形态；正文其余条目不变，与 2.3 一致的「单向加密」语义仍然成立。

| 项       | 已实现                                               | v1.2 原案                   | 偏离原因                               |
| -------- | ---------------------------------------------------- | --------------------------- | -------------------------------------- |
| 密码模型 | 全局主密码，只配置一次；忘记则所有加密笔记永久不可读 | 每条笔记独立密码（Q2 默认） | 用户明确要求                           |
| 解密位置 | 浏览器端 WebCrypto，服务端只存密文字节               | Go 服务端解密 + 内存会话    | 用户要求简化；本地单机场景增益等价     |
| 解锁会话 | 密钥仅存页面内存，刷新或点「锁定」即失效             | 服务端 10 分钟空闲会话      | 无服务端状态，天然满足「重启失效」     |
| 助记提示 | 单条问题文本，全局一份，如「你的生日是多少？」       | 每笔记最多 3 组问答         | 用户要求；不存答案，防泄露密码构成材料 |
| 正文长度 | ≤ 2000 个 Unicode 字符                               | ≤ 1 MiB                     | 用户要求                               |
| 分类     | 笔记可选分类，分类可增改删并有笔记计数               | 非目标（见 2.2）            | 用户要求，覆盖非目标                   |

| 术语       | 说明                                                                                                                                           |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 明文笔记   | `is_encrypted = 0` 的笔记，正文以明文保存在 SQLite 中。                                                                                        |
| 加密笔记   | `is_encrypted = 1` 的笔记，正文只以密文保存，标题仍为明文。                                                                                    |

### 5.3 加密笔记

#### 5.3.1 总原则

- 主密码只用于在浏览器内派生密钥，**不保存密码本身，也不保存密码哈希或校验值**；服务端能看到的只有 16 字节公开盐值与助记问题。密码是否正确由 AES-GCM 认证标签判定。
- 加密在浏览器完成：提交给服务端的已经是密文字节，服务端在同一行内写入 `is_encrypted=1`、`content=NULL`、`cipher`、`kdf_params`，由表级 CHECK 约束保证不出现半加密状态。
- 加密后正文列必须为 `NULL`；明文从未在该笔记的生命周期内落过盘（新建时即加密）。
- 不提供取消加密、重置主密码、导出明文等能力（MVP）。主密码可以修改（FR-3.16），但修改必须提供旧密码，且旧密码是否正确只由浏览器试解已有密文判定；服务端永远不具备验证口令的能力，所以「忘记旧密码」仍然等于「永久打不开」。
- 标题、创建/更新时间、分类、助记问题、加密状态属于明文元数据，这是设计取舍，必须在界面明确告知。
- 未解锁时页面不显示正文；所有 JSON 响应（含密文与明文正文）统一 `Cache-Control: no-store`。
- 刷新页面或点击顶栏「锁定」后密钥即刻失效，查看加密笔记需要重新输入主密码。

| FR-3.17 | P0     | 验证通过后逐条重加密：`decrypt(旧) → encrypt(新) → PUT /api/notes/{id}/cipher`，单条失败记录后继续跑完其余，汇总为「成功 N · 跳过 M · 失败 K」。只替换 `cipher` 与 `kdf_params`，标题、正文列、分类、`rev`、`updated_at` 逐字不变——改一次口令不该让全部笔记在「按更新时间倒序」的列表里排到最前。全局盐保持首次设置的值。                                                                                                                                                          |
| FR-3.18 | P0     | 重加密可中断可续跑：刷新或关闭页面后，流程用新密钥试解把已迁移的笔记判为「跳过」，从未迁移的笔记接着做，不需要任何持久化的迁移状态。续跑要填的口令由失败原因决定：全部是「提交失败」时新密码就是当前旧密码，界面预填它；出现「这条笔记不是用刚才那个旧密码加密的」时，那几条仍受上一代口令保护，界面不预填、按钮与提示明确要求输入**上一个**主密码。若清单里同时存在「更早一次口令保护的笔记」与「已迁移的笔记」，一次续跑只能推进其中一类，失败条目仍列在迁移状态卡里并说明原因。 |
| FR-3.19 | P0     | 助记问题可随时单独修改（`PUT /api/master-password/question`），不要求旧密码，也不换盐；长度校验同首次设置。                                                                                                                                                                                                                                                                                                                                                                        |

#### 5.3.3 加密流程（用户视角）

1. 首次勾选「用主密码加密这条笔记」时，若尚未配置主密码，编辑器把当前草稿存入页面内存（`editorDraft`，不写任何浏览器存储）并跳转 `/master-password?next=...`。
2. 设置页填写密码、确认密码与助记问题，勾选不可恢复警告后提交；浏览器生成 16 字节随机盐，只把盐和助记问题发给服务端，密码原文永不离开浏览器。
3. 设置成功后浏览器用 PBKDF2 派生出密钥并留在页面内存，流程回到编辑器，草稿仍在。
4. 若本会话还没有密钥、且这条笔记还没有密文可以当场验证密码，编辑器要求**两次输入主密码并比对一致**才继续——用记错的密码派生的密钥会把这条笔记永久锁死，而当时看不出任何异常。
5. 编辑器把正文在浏览器内加密为 `nonce‖密文‖tag`，提交密文与 `kdf_params`；服务端把密文写入 `cipher` 并将 `content` 置为 `NULL`。
6. 之后每次查看加密笔记的正文，都需要输入主密码解锁；解锁时按这条笔记自己声明的 `kdf_params` 派生密钥。

#### 5.3.4 解锁与查看流程

1. 打开加密笔记，页面只显示标题、时间、密码框与提示入口。
2. 输入主密码并提交，浏览器用 `master_password.salt` 派生密钥并本地解密，服务端不参与解密。
3. 密码正确：密钥驻留页面内存，正文按 Markdown 渲染展示；同一会话内浏览其他加密笔记不再询问密码。
4. 密码错误、密文损坏、跨笔记移植密文或 `kdf_params` 越界：统一提示「密码错误或数据损坏」，不提供任何区分信息，也不消耗任何次数。
5. 用户点击顶栏「锁定」清除本页密钥；刷新或关闭标签页同样失效。没有服务端会话，也没有空闲计时器。

#### 5.3.5 忘记密码流程

1. 用户在解锁页点击「忘记密码？」进入 `/notes/:id/forgot`。
2. 页面展示全局助记问题，并说明问题只用于唤起记忆，不参与解密、不校验答案。
3. 页面明确告知：没有密码找回、重置或后门，加密笔记正文将永久无法恢复。
4. 用户可以选择返回解锁页，或删除该笔记（删除不要求密码）。
5. 不存在任何「通过回答问题恢复」的路径。

#### 5.3.6 修改主密码流程（用户视角）

1. 顶栏用户名进入 `/info`，主密码卡点「修改主密码」，展开旧密码 + 新密码 + 确认新密码表单（可顺带更新助记问题）。
2. 浏览器取全局盐与加密笔记密文清单（`GET /api/notes/encrypted`，只有 id、密文与参数，没有标题和正文），用旧密码派生密钥并逐条试解，第一条能解开的即视为验证通过。没有加密笔记时跳过验证，只校验新密码两次一致。
3. 旧密码不当时界面报「主密码不正确或数据已损坏」，会话密钥不动、任何密文不写。
4. 验证通过后用新密码派生密钥，逐条 `decrypt(旧) → encrypt(新) → PUT /api/notes/{id}/cipher`；每条落定归入「成功 / 跳过 / 失败」，单条失败不中断其余。
5. 全部提交后会话密钥换成新密钥，**改密结果当场落地成迁移报告**，再重新读一遍清单复核还剩几条没迁移完；复核请求本身失败时沿用报告里的计数。附带步骤（顺带改助记问题、复核）失败只会追加一句「主密码已更新，但……」的提示，不会把已经成功的改密显示成失败，也不会让你误以为要拿旧密码重来一遍。还有未迁移的笔记时，迁移状态卡列出条目与原因，可点「继续迁移」；全部迁移完则提示「主密码已更新，N 条笔记已重新加密」。
6. 中途刷新或关页面后续跑，填哪个口令由失败原因决定：只有「提交失败」（网络/服务端）时新密码此刻就是旧密码，点「继续迁移」会把新密码预填进旧密码栏；报告里出现「这条笔记不是用刚才那个旧密码加密的」时，按钮改成「继续迁移（请输入上一个主密码）」且旧密码栏留空——那些条目仍受上一代口令保护，预填新密码只会让你再撞一次同样的失败。已迁移的笔记在任何一次续跑里都判为「跳过」，不会被二次加密。
7. 改密全程：新密码不进请求体、不进日志、不进任何浏览器存储；服务端只见得到一串对它不透明的密文字节。

#### 5.3.7 关键提示文案（必须出现在界面）

- 主密码设置页：
  > 主密码无法找回、无法重置，也没有后台可查询的通道。忘记它，所有加密笔记将永久打不开。
- 口令强度提示：
  > 建议使用 12 个字符以上的长口令：密钥由它派生，弱口令会被离线爆破。
- 助记问题填写区：
  > 助记问题以明文保存在本地数据库中，仅用于帮助你回忆密码。请勿在问题里直接写出密码。
- 忘记密码页：
  > 主密码没有找回、没有重置、也没有后台可查询的通道。忘记它，这条加密笔记就永久打不开了。
- 信息页改密表单：
  > 修改主密码需要你输入旧密码。忘记旧密码时没有任何找回途径，加密笔记只能删除。
- 迁移状态卡（仍有笔记没迁移完时）：
  > 还有 N 条笔记没迁移完，可以点「继续迁移」重试。失败条目逐条说明原因：「这条笔记不是用刚才那个旧密码加密的」或「提交失败（原因）」。前一种原因出现时按钮写成「继续迁移（请输入上一个主密码）」，且旧密码栏留空等用户输入上一个主密码。

- 写操作使用 JSON 请求体，由前端 `fetch` 发起；不使用页面表单直发，也不做服务端重定向。
- 成功后的页面跳转由前端路由完成，避免整页刷新。
- API 不启用 CORS，仅允许同源访问；开发环境通过 Vite 代理保持同源。
- 新建笔记的骨架文件（`note-example.md`）与 `note.yaml` 同目录：`note web` 启动时缺失才写入内置默认内容，**绝不覆盖**已存在的文件；文件不可读或配置目录不可写时服务照常启动，页面回退到内置默认骨架。骨架上限与正文一致（2000 码点），因为它会原样成为新笔记的正文。
- 服务端没有任何解密端点：加解密只在浏览器（或未来的 CLI）发生，`cipher` 对服务端是不透明字节。
- `POST /api/ai/optimize` 是唯一会主动发起对外网络的端点：它每次都重新读 `note.yaml`，把正文交给 `internal/ai` 代发，响应只回前端预览——不写库、不改笔记，用户确认后才会走正常的 `PUT /api/notes/{id}`。
- AI 配置的读写只碰 `note.yaml`：`GET /api/ai-config` 每次都从磁盘现读（手改 YAML 后刷新页面即生效），`PUT` 与 `note config set` 走同一个 `config.SetValues`，因此「命令行写的」和「网页写的」不可能出现两套规则。

### 5.6 首次引导（名字 + 初始主密码）

| 编号   | 优先级 | 需求                                                                                                                                                                                                                                                                                                                               |
| ------ | ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-5.1 | P0     | 引导页两步：步骤 1 收用户名，步骤 2 收**必填**的初始主密码（密码 + 确认 + 助记问题 + 不可恢复勾选）。没有「暂时跳过」，两步走完才算引导完成。                                                                                                                                                                                      |
| FR-5.2 | P0     | 引导完成判据为「名字已设 **且** 主密码已配置」（`decideStep(nameSet, masterConfigured)`）。页面主体与 `document.title` 共用同一判定，避免出现「还在引导却显示『XX的笔记』」。只按名字判断会漏掉「名字存好、密码还没设就刷新」这个半态，用户会绕过必填直接进主界面。                                                                |
| FR-5.3 | P0     | 步骤 1 保存名字成功后只在本地推进到步骤 2，不重读设置——重读会让引导页消失。                                                                                                                                                                                                                                                        |
| FR-5.4 | P0     | 步骤 2 挂载时先 `GET /api/master-password`：**未配置**渲染完整设置表单（生成随机盐 → `POST` → 用返回的盐派生密钥放进会话内存）；**已配置**（上一次 POST 成功但解锁前被打断）只渲染「输入主密码解锁」单输入框，不再生成盐、绝不重复 POST。这条幂等分支是必需的：POST 只允许一次，缺了它用户会被永久卡在引导页第二步，只能删库重来。 |

## 6. 页面与交互

页面数量控制在 10 个主视图内（引导、概览、列表、回收站、新建/编辑、详情、忘记密码、主密码、信息、404），无弹窗式复杂交互。前端为独立轻量 SPA，使用 Vite + Svelte 5 + TypeScript，不使用 SvelteKit；不引入 UI 组件库、CSS 框架、路由库或状态管理库，路由使用自写微型 History 路由；Markdown 渲染只用 `marked` + `dompurify` 两个依赖。

### 6.1 列表 / 搜索页

```
+------------------------------------------------------+
| 笔记                            [ 搜索词...... ] [搜] |
|                                        [ + 新建笔记 ] |
+------------------------------------------------------+
| 标题 A                                     2026-10-26 |
| 正文摘要（仅明文笔记）...                             |
+------------------------------------------------------+
| 已加密 · 标题 B                            2026-10-24 |
| （加密笔记不展示正文摘要）                            |
+------------------------------------------------------+
|                                    上一页  1/3  下一页 |
+------------------------------------------------------+
```

- 页头固定搜索框和「新建笔记」主按钮。
- 列表右侧常驻分类树：根节点「全部笔记」（总数、可展开收起）+「未分类」+ 各分类，每项显示笔记数；
  点分类即筛选，选中项高亮，条件写入 URL 的 `category` 参数。
- 加密笔记显示「已加密」标识，摘要位置固定写「密文内容不在列表展示。」
- 搜索状态在结果上方展示「共 N 条结果」及清除搜索入口。
- 无数据、无结果分别有独立空状态。
- 搜索框自动聚焦；搜索词同步到 URL 查询参数后调用 API，不做实时搜索。

### 6.2 明文笔记详情

- 展示标题、更新时间、所属分类、正文。
- 操作：编辑、锁定（会话已解锁时）、移入回收站、返回。加密笔记在未解锁时不给删除按钮（删除要求先解锁）。
- 正文按 Markdown 渲染展示（见 5.1.2 FR-1.2）。

### 6.3 加密笔记详情（未解锁）

- 展示标题、更新时间、「已加密」标识与所属分类。
- 主密码输入框、解锁按钮。
- 折叠的「查看密码提示」区域，展开后只展示助记问题文本。
- 「忘记密码？」链接。
- 不提供删除按钮：加密笔记要先解锁才能删除，提示写「解锁后才能删除这条加密笔记」。
- 不展示正文、摘要、字数或任何正文派生信息。

### 6.4 新建 / 编辑页

- 标题输入框、正文 `<textarea>`、分类下拉（默认「未分类」）。
- 右侧或下方实时 Markdown 预览（防抖 300 ms）；窄屏（≤1024px）预览区在编辑器下方堆叠，高度上限 50vh 并自带滚动。
- 正文字数按 Unicode 码点计数，超过 2000 拒绝提交。
- 可选「用主密码加密这条笔记」勾选框；未配置主密码时先跳 `/master-password`，草稿保存在页面内存。
- 编辑加密笔记时不显示密码字段：会话已解锁则自动带回明文，密钥失效则在本页给出解锁区，绝不出现空编辑器。
- 明确「保存」「取消」；不做自动保存。

### 6.5 主密码设置页

- 密码、确认密码、助记问题、口令强度提示与不可恢复确认项。
- 提交按钮上方固定展示不可恢复警告，确认项为必选，未勾选时提交按钮禁用。
- 警示文案不可折叠、不可默认勾选。
- 已配置过后页面转为只读，展示助记问题并说明「已经配置过了」，不再提供密码输入框。

### 6.6 忘记密码页

- 依次展示：助记问题、不可恢复说明、删除入口、返回入口。
- 页面没有密码输入框，也没有任何「回答问题即可恢复」的路径。
- 删除按钮需要二次确认，文案包含「永久删除」；删除是软删除后立刻彻底删除（这条笔记谁也解不开，留在回收站只是解不开也清不掉的残留）；删除后回到列表。

### 6.7 分类树（列表页内）

- 树列出分类名与笔记数，筛选、新增、改名、删除都在树内完成，不再有独立分类页。
- 新增为树底部的常驻输入框；改名为行内编辑（Enter 保存、Esc 取消）；删除为二次确认。
- 默认分类「未分类」不显示操作按钮。
- 删除被拒时在该行展示「分类下仍有 N 条笔记」；重名在输入框下展示「该分类名已存在」。
- 删除正在筛选的分类后回到「全部笔记」第 1 页。

### 6.8 反馈与异常状态

| 场景                     | 交互                                                                             |
| ------------------------ | -------------------------------------------------------------------------------- |
| 表单校验失败             | 原页面回显输入，字段下方显示具体错误；密码字段不回显原值。                       |
| 创建/更新成功            | 前端路由跳转详情页；顶栏显示一次性提示（toast）。                                |
| API 404                  | 前端展示统一错误视图，提供返回列表链接。                                         |
| API 405/500              | 前端展示通用错误提示，不泄露内部细节。                                           |
| 加密笔记未解锁进入编辑页 | 本页给出解锁区，解锁后自动带回正文；不存在服务端会话过期返回 401 的情况。        |
| 解密失败                 | 统一「密码错误或数据损坏」；解锁页保留输入框，编辑器清空预览并给出重新解锁入口。 |
| 删除确认                 | 浏览器原生确认，文案包含「永久删除」。                                           |

### 6.9 可访问性与响应式

- 使用语义化 HTML、`label` 正确关联输入框，支持键盘完成全部操作。
- 断点两档、按内容而非设备：**≤1024px** 收成单列（编辑页预览落到正文下方并自带滚动，分类树提到列表上方）；**≤640px** 进入触控布局（顶栏两行且导航可横向滚动、列表变卡片、动作按钮整行）。
- 窄屏（≥360px）不出现页面级横向滚动；唯一允许横向滚动的是热力图自身容器——53 周语义不压缩，窄屏显示「左右滑动可查看全年」提示。
- 触控目标不低于 44×44 px（按钮、导航链接、分类行内操作）；输入框字号不低于 16px，避免 iOS 聚焦时页面自动放大。
- 不依赖 hover 触发任何功能：分类行内操作在触摸设备与窄屏上常显。
- 使用 `100dvh` 处理移动端地址栏收放，用 `env(safe-area-inset-*)` 避开刘海与手势条（`viewport-fit=cover`）。
- 长标题、长查询词、长路径与报错文案就近换行（`overflow-wrap: anywhere`），不撑破容器。
- 颜色对比满足基本可读性；不用颜色作为唯一状态提示。
- 核心流程由前端应用完成，要求启用 JavaScript；提供 `<noscript>` 提示。
- 路由切换后更新 `document.title`，并将焦点移动到主标题，保证读屏与键盘可用。

## 7. 非功能需求

### 7.1 安全与隐私

| 编号    | 要求                                                                                                                                                                                                                                                               |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| NFR-S1  | 加密算法使用 AES-256-GCM（浏览器 WebCrypto）；密钥由 PBKDF2-HMAC-SHA256 从全局主密码派生（16 字节随机盐、`iter=150000`、`keylen=32`）；盐为公开参数，仅主密码本身不落盘。                                                                                          |
| NFR-S2  | 不保存密码、密码哈希或独立的密码校验值；数据库里只有派生用的盐；错误密码由 GCM 认证失败识别。                                                                                                                                                                      |
| NFR-S3  | 密文使用随机 12 字节 nonce，并将笔记 ID 与格式版本（`note:v1:`）作为 AAD，防止密文跨笔记移植。                                                                                                                                                                     |
| NFR-S4  | 启用 `secure_delete`；**彻底删除**（`?purge=1`）后执行 WAL checkpoint，退出时再次 checkpoint。软删除只打 `deleted_at`，回收站期间正文/密文仍在库里（这是可恢复的前提），因此「删除即清页」只对彻底删除成立。加密笔记的明文从未写入数据库，因此重加密无需额外清理。 |
| NFR-S5  | 应用默认仅监听 `127.0.0.1`；绑定非回环地址必须显式传入 `note web --allow-remote`（或 `--remote`）并打印风险警告。                                                                                                                                                  |
| NFR-S6  | 所有写请求（POST/PUT/DELETE）校验 Origin/Sec-Fetch-Site，并使用双提交 CSRF Token；校验 Host，防 DNS Rebinding。                                                                                                                                                    |
| NFR-S7  | 所有动态 API 响应（含返回密文的笔记详情）返回 `Cache-Control: no-store`；HTML 入口返回 `Referrer-Policy: no-referrer` 等安全头。                                                                                                                                   |
| NFR-S8  | 日志不得包含正文、密码、提示答案、完整查询串、Cookie 或表单内容。                                                                                                                                                                                                  |
| NFR-S9  | 不引用任何外部 CDN、字体、脚本或图片；前端构建产物全部通过 `go:embed` 内嵌到二进制。                                                                                                                                                                               |
| NFR-S10 | 数据库文件权限在 POSIX 下为 `0600`，数据目录为 `0700`（Windows 依赖用户账户隔离）。                                                                                                                                                                                |
| NFR-S11 | 前端不得将密码、解密正文或解锁密钥写入 `localStorage`、`sessionStorage` 或 IndexedDB，仅允许存在于当前页面内存。                                                                                                                                                   |

### 7.2 性能

| 编号   | 指标                                                                          |
| ------ | ----------------------------------------------------------------------------- |
| NFR-P1 | 冷启动到可访问页面 ≤ 2 秒（常规 SSD）。                                       |
| NFR-P2 | 10,000 条笔记、约 100 MB 文本下，列表 API 服务端处理 ≤ 100 ms。               |
| NFR-P3 | 同等数据量下，搜索请求服务端处理 ≤ 300 ms。                                   |
| NFR-P4 | 浏览器端解锁的 PBKDF2 派生预期耗时 100–500 ms，属于安全成本，不视为性能缺陷。 |
| NFR-P5 | 服务端不再有解密与 KDF 路径：`cipher` 只做字节存取，单条笔记读写 ≤ 10 ms。    |
| NFR-P6 | 常驻内存通常 < 100 MB；派生与解密开销发生在浏览器进程，不计入服务端。         |
| NFR-P7 | Markdown 预览防抖 300 ms，编辑大段正文时输入不卡顿。                          |
| NFR-P8 | 前端首屏 JS/CSS（gzip）≤ 150 KB；不使用大图、Web 字体和动画库。               |

### 7.3 兼容与部署

- Go 1.26 及以上；使用标准库 `net/http` 方法路由。
- Node.js 22 LTS 及以上（建议 24 LTS）仅用于前端开发和构建；运行机不需要 Node/npm。
- 前端为独立工程 `web/`（Vite + Svelte 5 + TypeScript，不使用 SvelteKit）；Vite 构建输出到 `internal/web/dist`，由 `//go:embed` 内嵌。
- SQLite 驱动使用纯 Go 实现（`modernc.org/sqlite`），`CGO_ENABLED=0` 可构建。
- 支持 Windows 10/11、macOS、Linux（amd64/arm64）。
- 浏览器：最近两个大版本的 Chrome、Edge、Firefox、Safari，且必须启用 JavaScript；移动端 Safari/Chrome 与桌面同源，用 `clamp()`、`minmax()`、`dvh`（回落 `vh`）与 `env(safe-area-inset-*)`，不引入任何前缀或 polyfill。
- 构建产物为单个二进制；不单独部署前端，不分发 `node_modules`。
- SPA 使用 History 路由；Go 对非 API 的 GET 请求回退 `index.html`。

### 7.4 可靠性

- 所有多步写操作使用事务；加密操作必须原子完成。
- 崩溃后数据库应保持可打开、可恢复状态（WAL 模式）。
- 启动时执行 schema 迁移并校验数据库完整性；失败时拒绝启动并输出明确错误。
- 支持 SIGINT/SIGTERM 优雅退出，关闭前执行 WAL checkpoint。
- 文件损坏时应用不得尝试静默重建数据；应保留原文件并提示用户从备份恢复。

### 7.5 可维护性

- 依赖数量保持最小；后端不使用 Web 框架、ORM；前端不引入 UI 组件库、CSS 框架、路由库、状态管理库，使用 Svelte 内置能力。
- 前端提交 `package-lock.json`，构建统一使用 `npm ci`；Node 版本通过 `.nvmrc`/`engines` 固定。
- 前后端通过 `/api` JSON 契约交互；API 客户端集中管理，不在组件中散落请求逻辑。
- 加密参数、格式版本作为常量集中管理，并在密文中可追溯。
- 核心模块（加密、存储、HTTP 处理器、前端 API 客户端）具备单元测试或集成测试。
- 数据库结构变更通过带版本号的迁移脚本完成。

### 7.6 威胁模型

| 威胁                                  | 是否防护 | 说明                                                                                                                   |
| ------------------------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------- |
| 数据库文件被复制、误发或随备份泄露    | 部分     | 正文为密文；标题、分类、助记问题、时间、数量仍为明文。PBKDF2 下弱口令可被离线爆破。                                    |
| 磁盘被离线读取                        | 部分     | 同上，安全性取决于口令长度与 PBKDF2 成本；界面要求使用 12 字符以上长口令。                                             |
| 同机其他用户直接操作正在运行的应用    | 否       | MVP 无应用级登录；依赖操作系统账户隔离。                                                                               |
| 键盘记录、屏幕截图、内存抓取          | 否       | 任何本地明文展示工具都无法防御。                                                                                       |
| 浏览器前进/后退缓存短暂显示已锁定内容 | 部分     | 使用 `no-store`；不保证浏览器进程内存被立即清除。                                                                      |
| 恶意站点跨站发起写请求                | 是       | Origin 校验 + CSRF Token + SameSite Cookie + JSON Content-Type。                                                       |

| DNS Rebinding 访问本地服务            | 是       | Host 白名单 + 默认仅回环监听。                                                                                         |
| SSD 物理层残留旧明文                  | 否       | 超出应用层能力；应用只保证逻辑删除与 WAL 清理。                                                                        |

### 8.3 数据模型

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA secure_delete = ON;
PRAGMA busy_timeout = 5000;
PRAGMA foreign_keys = ON;

CREATE TABLE IF NOT EXISTS categories (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    name       TEXT NOT NULL UNIQUE COLLATE NOCASE,
    created_at TEXT NOT NULL
);
-- id=1「未分类」由迁移插入，不可改名、不可删除。

CREATE TABLE IF NOT EXISTS master_password (
    id         INTEGER PRIMARY KEY CHECK (id = 1),  -- 单行表
    salt       BLOB NOT NULL,                       -- 16 字节随机盐（公开 KDF 参数）
    question   TEXT NOT NULL,                       -- 助记问题，明文，不含答案
    created_at TEXT NOT NULL
);
-- 只存盐，不存密码、密码哈希或任何校验值。

CREATE TABLE IF NOT EXISTS notes (
    id           TEXT PRIMARY KEY,              -- UUID v4
    title        TEXT NOT NULL,                 -- 明文标题
    content      TEXT,                          -- Markdown 原文；加密后必须为 NULL
    is_encrypted INTEGER NOT NULL DEFAULT 0 CHECK (is_encrypted IN (0, 1)),
    cipher       BLOB,                          -- nonce(12) || ciphertext || tag(16)
    kdf_salt     BLOB,                          -- 加密时冗余写入 master_password.salt 副本
    kdf_params   TEXT,                          -- JSON，见 8.4.1
    hints        TEXT,                          -- v1 遗留列，v1.3 起不再写入
    category_id  INTEGER REFERENCES categories(id),  -- NULL 或 1 = 未分类
    kind         TEXT,                          -- v1.2 遗留列
    remark       TEXT,                          -- v1.2 遗留列
    rev          INTEGER NOT NULL DEFAULT 1,    -- 乐观并发计数
    created_at   TEXT NOT NULL,                 -- RFC3339 UTC
    updated_at   TEXT NOT NULL,
    CHECK (
        (is_encrypted = 0
            AND content IS NOT NULL
            AND cipher IS NULL
            AND kdf_salt IS NULL
            AND kdf_params IS NULL
            AND hints IS NULL)
        OR
        (is_encrypted = 1
            AND content IS NULL
            AND cipher IS NOT NULL
            AND kdf_salt IS NOT NULL
            AND kdf_params IS NOT NULL)
    )
);

CREATE INDEX IF NOT EXISTS idx_notes_updated_at
    ON notes(updated_at DESC);
```

- 客户端以 `master_password.salt` 为准；与 `notes.kdf_salt` 不一致时视为数据损坏并拒绝解密。
- 迁移使用 `PRAGMA user_version` 记录版本，启动时按序执行并置于事务内；当前版本为 5。
- 搜索规模较小时依赖 `updated_at` 索引与全表扫描；数据量增长后再评估 FTS5。
- 单连接写入或短事务写入；WAL 允许读并发，个人场景足够。

### 8.4 加密设计

规范全文见 `docs/superpowers/specs/2026-10-27-note-crud-category-encryption-design.md` 第 2 节；本节是落地摘要，未来的 CLI 或非浏览器客户端按本节即可实现互操作。

#### 8.4.1 参数

| 项目         | 值                                                                                 |
| ------------ | ---------------------------------------------------------------------------------- |
| KDF          | PBKDF2-HMAC-SHA256                                                                 |
| 迭代次数     | 150000                                                                             |
| 派生密钥长度 | 32 字节                                                                            |
| 盐           | 16 字节随机值，全局一份（`master_password.salt`），加密时冗余写入 `notes.kdf_salt` |
| AEAD         | AES-256-GCM，12 字节随机 nonce                                                     |
| AAD          | `note:v1:` + 笔记 ID 的字节串                                                      |
| 密文存储     | `nonce ‖ AES-GCM 输出（含 16 字节 tag）`，数据库为 BLOB，HTTP 为 base64            |
| 密码规范化   | NFC                                                                                |

`kdf_params` 实际值：

```json
{ "algo": "pbkdf2", "prf": "HMAC-SHA256", "iter": 150000, "keylen": 32 }
```

读取时必须校验参数边界：`iter ∈ [100000, 1000000]`、`keylen = 32`、`algo = pbkdf2`、`prf = HMAC-SHA256`。超出范围视为数据损坏并拒绝解密，防止被篡改的数据库参数导致内存或 CPU 耗尽。

#### 8.4.2 加密（浏览器，伪代码）

```text
salt   = random(16)                       -- 仅在主密码设置页生成，随问题一起 POST
key    = PBKDF2(NFC(password), salt, iter=150000, len=32)
nonce  = random(12)
aad    = "note:v1:" + noteID
cipher = nonce ‖ AESGCM(key).Seal(nonce, utf8(content), aad)

POST /api/notes  { title, cipher_b64, kdf_params, category_id, encrypted: true }
  → 服务端在一个事务内写入 cipher/kdf_salt/kdf_params，content = NULL
```

- 密码原文与派生密钥都不发往服务端；服务端只见 base64 密文字节。
- 新建加密笔记时先生成一个本地 UUID 作为 AAD 绑定，再提交；跨笔记移植密文无法解密。
- 事务失败时不得修改任何字段，明文保持不变。

#### 8.4.3 解密（任意客户端，伪代码）

```text
row    = SELECT cipher, kdf_salt, kdf_params FROM notes WHERE id = :noteID
params = parse_and_validate(row.kdf_params)
key    = PBKDF2(NFC(password), master_password.salt, params)
plain, err = AESGCM(key).Open(cipher[0:12], cipher[12:], aad="note:v1:"+noteID)
if err: return generic_error("密码错误或数据损坏")
```

- 解密失败不得区分「密码错误」「nonce 有问题」「tag 不匹配」「参数越界」。
- 明文只在浏览器内存中存在；API 响应与浏览器存储都不得持久化正文。

#### 8.4.4 编辑重加密

- 页面内存持有会话密钥时进入编辑器即自动带回明文；密钥失效则在本页给出解锁区。
- 使用同一密钥、新的 12 字节 nonce 重新加密，更新 `cipher` 与 `updated_at`；盐与 KDF 参数不变，不修改主密码。
- 正文列仍为 `NULL`，编辑过程不产生明文落盘。

#### 8.4.5 明文残留处理

- 全局启用 `PRAGMA secure_delete = ON`，删除/覆盖的页内容以零填充。
- 软删除（回收站）不清页：它只写 `deleted_at`，正文/密文仍在库里，硬删除后由 SQLite 的 `secure_delete` 清零。
- 彻底删除（`?purge=1`）事务提交后执行 `PRAGMA wal_checkpoint(TRUNCATE)`，关闭应用时再次 checkpoint。
- 加密笔记的明文从未写入数据库，因此加密与重加密无需额外清理；已用脚本验证：`.run/plaintext-residue.mjs` 在数据库文件与 WAL 中检索不到加密正文哨兵，而明文对照笔记的正文可以在 WAL 中检索到。
- 定期维护（可选、手动）执行 `VACUUM` 重写数据库文件；MVP 不自动对大数据量执行。
- 明确边界：备份文件、文件系统快照、SSD 磨损均衡层可能保留旧数据，应用无法保证物理擦除。

#### 8.4.6 为什么没有密码校验哈希

独立保存密码哈希会额外提供离线爆破目标，且与 AEAD 的认证能力重复。直接让 GCM tag 校验密码，可以在不增加泄露面的情况下判断密码是否正确。代价是每次校验都必须完整执行 KDF 和解密，这对本产品可接受。

### 8.5 解锁会话

- 密钥只存在于当前页面的 JS 变量（`web/src/lib/session-key.ts`）：不写 SQLite、日志、Cookie、`localStorage`、`sessionStorage` 或 IndexedDB。
- 生效范围：同一浏览器标签页内的所有加密笔记；`hasKey` store 驱动顶栏「锁定」按钮显隐。
- 失效条件：刷新、关闭标签页、点击顶栏「锁定」。**没有服务端会话，没有空闲计时器**——这是相对 PRD v1.2 的简化取舍。
- 锁定同时清掉内存草稿（`editorDraft`），因为草稿里可能已经装着解密出来的正文。
- 边界：锁定只影响本页面之后的行为，已经渲染到屏幕上的正文需要用户自行离开页面；锁屏前应锁定或关闭标签页。

### 8.6 HTTP 与 API 约定

| 场景                          | 状态码 | 响应                                                                    |
| ----------------------------- | ------ | ----------------------------------------------------------------------- |
| 创建成功                      | 201    | 新笔记 JSON                                                             |
| 读取/更新/列表/统计成功       | 200    | 对应 JSON                                                               |
| 删除成功                      | 204    | 无响应体                                                                |
| 参数校验失败                  | 400    | `{"error":{"code":"validation_failed","message":"...","fields":{...}}}` |
| 请求体不是 JSON               | 400    | `code=body_invalid`                                                     |
| Host 校验失败                 | 400    | `code=host_invalid`                                                     |
| CSRF/Origin 校验失败          | 403    | `code=csrf_invalid`                                                     |
| 未找到笔记或分类              | 404    | `code=not_found`                                                        |
| 方法不允许                    | 405    | `ServeMux` 默认响应                                                     |
| 加密笔记改回明文              | 409    | `code=encrypted_immutable`                                              |
| 未设置主密码就提交密文        | 409    | `code=master_password_missing`                                          |
| 客户端生成的笔记 ID 撞库      | 409    | `code=id_conflict`                                                      |
| 改名/删除默认分类             | 409    | `code=category_reserved`                                                |
| 删除仍有笔记的分类            | 409    | `code=category_not_empty`，`fields.note_count` 为笔记数                 |
| 重复设置主密码                | 409    | `code=master_password_exists`                                           |
| 恢复/彻底删除未在回收站的笔记 | 409    | `code=not_in_trash`，文案「这条笔记不在回收站」                         |
| 请求体超限                    | 413    | `code=body_too_large`                                                   |
| 内部错误                      | 500    | `code=internal`，通用文案，不返回堆栈                                   |

- 没有 401：加解密在浏览器完成，服务端没有会话，也就没有「未解锁」状态。
- POST/PUT 请求使用 `application/json; charset=utf-8`，请求体上限沿用 `decodeJSON` 的限制；DELETE 允许空请求体，但同样需要 CSRF 头。
- 除 204 外，所有 API 响应使用 `Content-Type: application/json; charset=utf-8`，并返回 `Cache-Control: no-store`。
- 成功不返回 303；页面导航由前端路由完成。
- 错误响应统一为 `{"error":{"code":"...","message":"...","fields":{...}}}`；`message` 可直接展示，不得包含内部细节。
- CSRF：`GET /api/csrf` 返回 Token 并写入 `HttpOnly`、`SameSite=Strict` 的 Cookie；写请求在 `X-CSRF-Token` 头携带同一 Token，服务端同时校验头、Cookie、Origin/Sec-Fetch-Site。校验失败时前端刷新 Token 后重试一次。
- API 不启用 CORS，不返回 `Access-Control-Allow-*`；Vite 开发服务器通过代理将 `/api` 转发到 Go，生产由 Go 同源提供页面与 API。
- SPA 回退仅处理无扩展名或 `Accept: text/html` 的 GET 请求；`/api/*` 与 `/assets/*` 不参与回退。
- 加密笔记的详情响应含 `encrypted: true` 与 base64 密文，永不含 `content`；是否解锁由浏览器决定，服务端无从知晓。
- 标题去首尾空白后校验；正文不去空白，按 Markdown 原文存储，渲染只在浏览器发生。

### 8.7 搜索实现

```sql
-- :pattern = "%" || escaped(q) || "%"，escaped 将 \ % _ 转义
SELECT n.id, n.title, n.content, n.is_encrypted, n.category_id, c.name, n.updated_at
  FROM notes n LEFT JOIN categories c ON c.id = n.category_id
 WHERE (n.title LIKE :pattern ESCAPE '\'
        OR (n.is_encrypted = 0 AND n.content LIKE :pattern ESCAPE '\'))
   AND n.category_id = :category          -- 仅当 category > 0 时追加
 ORDER BY CASE WHEN n.title LIKE :pattern ESCAPE '\' THEN 0 ELSE 1 END,
          n.updated_at DESC,
          n.id DESC
 LIMIT 20 OFFSET :offset;
```

- 转义顺序：先将 `\` 替换为 `\\`，再将 `%` 替换为 `\%`、`_` 替换为 `\_`。
- SQLite `LIKE` 默认对 ASCII 大小写不敏感，对非 ASCII 为精确子串；满足中文搜索需求。
- 分页总数使用同条件的 `COUNT(*)` 查询。
- 加密笔记正文为 `NULL`，条件中显式排除，避免未来实现误查。
- 结果摘要由 Go 截断到 140 个码点并把换行折叠为空格，字段名为 `summary`；列表页对加密笔记不返回摘要。
- 摘要与标题都以 Svelte 文本插值渲染，不进 Markdown 管道。
- 搜索词通过 GET 参数传递，会出现在浏览器地址栏与历史记录中；这是本地单用户场景下的有意的简单取舍，服务端日志仍不记录查询串。
- 性能不足时的演进方向：SQLite FTS5 `trigram` 索引，仅索引明文笔记。

### 8.8 安全中间件

按顺序执行：

1. **请求恢复**：捕获 panic，记录不含敏感数据的堆栈摘要，返回 500。
2. **Host 校验**：默认允许 `127.0.0.1`、`localhost`、`[::1]` 及配置端口；显式启用 `note web --allow-remote` 时，额外允许配置的监听主机；其他 Host 返回 400。
3. **安全响应头**：
   - `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; form-action 'self'; frame-ancestors 'none'; base-uri 'none'`
   - `X-Content-Type-Options: nosniff`
   - `X-Frame-Options: DENY`
   - `Referrer-Policy: no-referrer`
   - API 与 HTML 入口使用 `Cache-Control: no-store`；带内容哈希的 `/assets/*` 使用 `public, max-age=31536000, immutable`
   - CSP 对生产构建生效；开发模式由 Vite 提供页面，不强制该策略
4. **CSRF**：`GET /api/csrf` 签发随机 Token Cookie；写请求同时校验 `X-CSRF-Token` 头、Cookie、Origin/Sec-Fetch-Site。
5. **访问日志**：记录方法、路由模式、状态码、耗时、响应字节数；不记录查询串、请求体、Cookie、密码或正文。
6. **超时**：`ReadHeaderTimeout=5s`、`ReadTimeout=15s`、`WriteTimeout=30s`、`IdleTimeout=60s`。

### 8.9 配置与运行

v1.5 起后端是 CLI 子命令形态：`note` 不带子命令等价于 `note help`（打印帮助），`note web` 是唯一启动前端页面的命令，`note info` 输出软件与运行信息。v1.9 起可以用 `note add` 在终端里直接写笔记（明文），不必开浏览器。v1.6 起 `note web` 拆出三个子命令，可以不占终端后台跑。v1.11 起 `note status` 输出使用统计：埋点在数据层（`internal/store`），网页与 CLI 的操作都计入同一本账簿。v1.12 起打开笔记就复制原文：`note show` 不给 id 会先进选择器，三条 CLI 路径与网页详情页都有一键复制（复制的是库里的 Markdown、不是渲染结果），`note list` 的筛选也命中正文。v1.13 起 `note.yaml` 多了 `ai` 段三项，命令行用 `note config` 读写（信息页「AI 配置」卡片读写的也是它）。v1.15 起 `note set / get / del` 让终端也能按标题读写单条笔记（不必开浏览器），默认落在内置分类「速记」。

开发模式（两个终端）：

```bash
# 终端 1：Go API 与内嵌页面（需已构建过 dist）
go run ./cmd/note web

# 终端 2：Vite 开发服务器，/api 代理到 127.0.0.1:8080
cd web && npm ci && npm run dev
```

构建与发布：

```bash
# 前端产物直接写入 Go 项目
cd web && npm ci && npm run build
cd ..

# 编译单二进制，前端已内嵌
CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o note ./cmd/note
```

`web/vite.config.ts` 关键配置：

```ts
import { defineConfig } from "vite";
import { svelte } from "@sveltejs/vite-plugin-svelte";

export default defineConfig({
  plugins: [svelte()],
  build: {
    outDir: "../internal/web/dist",
    emptyOutDir: true,
  },
  server: {
    proxy: {
      "/api": {
        target: "http://127.0.0.1:8080",
        changeOrigin: true,
      },
    },
  },
});
```

- 使用 `@sveltejs/vite-plugin-svelte` 编译 Svelte，`svelte.config.js` 启用 `vitePreprocess()` 处理 TypeScript；不引入 SvelteKit、SSR/SSG 或文件路由。
- 发布统一使用 `just build`，固定执行「前端构建 → Go 编译」，避免产物不同步。
- `internal/web/dist` 为生成物，不提交版本库；未生成时 `go build` 会因 `//go:embed` 找不到文件而失败，属于预期的构建保护。
- 首次进入开发或拉取新代码后，先执行一次 `cd web && npm ci && npm run build`，再启动 Go；之后前端改动由 Vite 开发服务器负责，无需反复构建 dist。
- `changeOrigin: true` 保证代理后的 Host 为 `127.0.0.1:8080`，通过 Go 的 Host 白名单校验。
- 开发代理还必须把 Origin 重写为 `http://127.0.0.1:8080`；否则浏览器 Origin 与代理后的 Host 不一致，写请求会被 Origin 校验拒绝（完整配置见技术方案 10.1）。
- Node/npm 只存在于构建机和开发机；部署机只需要二进制和数据目录。
- 启动流程：解析参数 → 创建数据目录（权限 0700）→ 打开数据库并设置 PRAGMA → 执行迁移 → 校验 schema → 装配 API、静态资源与 SPA 回退 → 监听。失败时输出明确错误并以非零码退出。

后台运行（v1.6）：

- `note web start` 用同一二进制重新执行自身（Go 没有 fork）：Unix 新会话（`Setsid`），Windows 分离进程组 + 隐藏窗口，因此关闭终端不影响后台实例。
- 状态文件 `note.json` 与日志 `note.log` 固定在数据库所在目录（`filepath.Dir(DBPath)`）。状态文件权限 `0600`、原子写（临时文件 + rename），记录 `pid` / 监听地址 / 可点击地址 / 启动时间 / 数据库路径 / 日志路径 / 版本；日志追加写、不轮转。
- 日志由父进程在文件描述符层接管（子进程 stdout/stderr 指向 `note.log`）——服务端日志句柄在启动时就绑定了当时的 stderr，运行期改不了。
- `stop` 走 `POST /api/shutdown`：携带状态文件里的关停令牌。打到前台实例（无有效状态文件但端口有响应）时只提示回终端 Ctrl+C 并以 1 退出，不按 pid 猜着杀进程。
- 同一目录只有一个状态文件，所以同一目录下换一个 `--db` 视为「已被另一个实例登记」，`start` / `stop` 都拒绝执行并提示，不会覆盖别人的状态文件。
- 前台与后台是同一套服务代码，页面与 API 完全一致；带正文的响应仍为 `no-store`，令牌不落日志、不进响应、不进命令行、不进环境变量。

### 8.10 日志

- 前台模式输出到 stdout，后台模式输出（同格式、同字段）到数据库同目录的 `note.log`；`start` 失败时打印该文件的最后 20 行帮助定位。
- 格式为结构化单行文本或 JSON。
- 字段：时间、级别、方法、路由模式、状态码、耗时、响应大小。
- 禁止字段：请求体、密码、笔记正文、密文、查询词、Cookie、Authorization、关停令牌。
- 服务端不参与加解密，因此没有解密失败日志；只有 API 状态码与错误类别。
- 启动时记录数据库路径（不含敏感信息）。
- 监听成功后打印可直接点击的访问地址（`http://host:port`，IPv6 加方括号），每地址一行；通配绑定时枚举本机非回环地址。

### 8.11 备份与数据迁移

- 备份对象：`notes.db` 及可能存在的 `notes.db-wal`、`notes.db-shm`；后台模式下同目录还有 `note.log`（日志，可删）与 `note.json`（运行状态，可删）。推荐先 `note web stop` 再备份；如库仍在被写，可 `sqlite3 notes.db ".backup 'backup.db'"`。
- `note.json` 里存着关停令牌与 pid：它只是运行期凭据，不影响数据完整性，删掉只会让 `stop` / `status` 失去线索（下次 `start` 会当作残留清理）。备份给别人前建议连它一起排除。
- 加密笔记在备份中保持密文；明文笔记在备份中仍是明文，需由用户自行保护备份。
- 备份可能包含加密前的历史明文（例如旧备份），应用无法追溯清理。
- 迁移：复制整个数据目录到新机器，保持文件权限；应用启动时执行 schema 迁移，不改变已有密文。

### 8.12 前端工程约束

- 目录 `web/` 为独立工程：Vite + Svelte 5 + TypeScript；TypeScript 开启 `strict`；不使用 SvelteKit。
- 不引入 UI 组件库、CSS 框架、路由库、状态管理库、SSR/SSG 框架；组件和样式手写。
- 使用 Svelte 内置 scoped CSS 与少量全局 CSS；状态使用 Svelte 5 runes 或内置 stores，不引入额外状态库。
- 路由使用自写微型 History 路由（约 60 行），Go 负责回退 `index.html`，未知 API 仍返回 JSON 404。
- API 访问集中在 `src/lib/`（`api.ts` + `notes.ts` 等领域客户端），统一处理错误码与 CSRF Token 刷新重试；不在组件内散落 `fetch`。
- 加解密集中在 `src/lib/crypto.ts`，会话密钥在 `src/lib/session-key.ts`，草稿在 `src/lib/draft.ts`：视图层不直接调用 WebCrypto。
- `{@html}` 只允许出现在 `components/Markdown.svelte`，其输入必须先经 `src/lib/markdown.ts` 的 `DOMPurify.sanitize`。
- 除 `Markdown.svelte` 以外禁止 `{@html}`；标题、摘要、分类名、助记问题只通过 `{...}` 文本插值渲染。
- 密码、解密正文和派生密钥不得写入 `localStorage`、`sessionStorage` 或 IndexedDB；解锁态由页面内存中的密钥维持，唯一持久化的前端偏好是主题选择。
- 页面刷新即失去解锁态，需要重新输入主密码；锁定后前端不得保留正文或草稿缓存。
- 构建使用 `npm ci` 与提交的 `package-lock.json`；Node 版本固定为 22 LTS 及以上（建议 24 LTS，`.nvmrc`/`engines`）。
- 类型检查使用 `svelte-check --tsconfig ./tsconfig.json`；加密、Markdown 净化、API 客户端、路由匹配与工具函数使用 Vitest 测试（DOM 相关用例按文件启用 `// @vitest-environment jsdom`）。
- 初始加载的 JS/CSS 目标 ≤ 150 KB（gzip），不使用大图、Web 字体和动画库。

### 9.2 验证明文残留的具体方法

1. 在运行的应用里创建两条笔记：一条勾选加密、正文含唯一标记 `PLAINTEXT_MARKER_20261027`；另一条保持明文、正文含对照标记 `CONTROL_MARKER_20261027`（用于证明检索手段本身有效）。
2. 等待删除接口触发 checkpoint，或直接优雅关闭应用（关闭时执行 `wal_checkpoint(TRUNCATE)`）。
3. 对 `data/notes.db`、`data/notes.db-wal` 执行：

   ```bash
   grep -a "PLAINTEXT_MARKER_20261027" data/notes.db data/notes.db-wal
   grep -a "CONTROL_MARKER_20261027" data/notes.db data/notes.db-wal
   ```

4. 预期：第一条无匹配，第二条至少匹配一次。加密正文从未进入请求体以外的任何环节，因此它连 WAL 都不该出现。
5. 若匹配到旧备份或文件系统快照，不属于运行时数据库泄漏，但需在文档中提示用户。

| R1   | 用户忘记主密码，所有加密笔记永久打不开 | 高   | 强制勾选确认项；设置页推荐使用密码管理器；界面提示使用 12 字符以上长口令；文档反复说明；默认不勾选加密。                                                                                 |
| R2   | 助记问题泄露口令线索                   | 中   | 问题明文保存并在填写区告知；只存问题、不存答案，无法用于校验或解密；限制 100 字符。                                                                                                      |
| R3   | 标题、分类、时间、助记问题仍为明文     | 中   | 明示元数据边界；后续版本可评估标题加密（会牺牲列表搜索）。                                                                                                                               |
| R4   | 弱口令被离线爆破                       | 高   | PBKDF2-HMAC-SHA256 迭代 150000（浏览器可用上限附近）；界面要求 12 字符以上长口令；不夸大安全承诺。这是相对 PRD v1.2（Argon2id 内存困难）的已知降级，换取零服务端密码学与跨客户端可解密。 |
| R5   | WAL、备份、快照中残留旧明文            | 中   | `secure_delete`、彻底删除后 checkpoint、退出 checkpoint；加密笔记的明文从未落盘；文档说明备份边界。                                                                                      |
| R6   | LIKE 全表扫描在超大数据量下变慢        | 中   | 限制单条 2000 字符；设定 10k/100 MB 指标；后续引入 FTS5 trigram。                                                                                                                        |
| R7   | 解锁期间内存或屏幕泄露                 | 中   | 密钥只在当前标签页内存、手动锁定即清除并连带清掉草稿、`no-store`；明确无法防御本机恶意程序。                                                                                             |
| R8   | 应用被暴露到公网                       | 高   | 默认回环监听；`note web --allow-remote` 显式开启并警告；MVP 不提供公网认证。                                                                                                             |
| R9   | 前端工具链与 npm 依赖带来供应链风险    | 中   | 只保留 Vite/Svelte/TypeScript/Vitest 等必要依赖；提交锁文件；使用 `npm ci`；固定 Node 22 LTS 及以上；定期审计。                                                                          |
| R10  | 前端产物与 Go 二进制不同步，或忘记构建 | 中   | 统一使用 `just build`；从干净目录构建；`dist` 不提交；embed 缺失时构建失败；发布前执行 AC-25。                                                                                           |

## 附录 B：安全自检清单

- [ ] 数据库里只有派生用的盐（`master_password.salt` 与 `notes.kdf_salt` 副本），不存在密码、密码哈希或校验值。
- [ ] 密文使用随机 nonce，AAD 绑定笔记 ID 与格式版本，跨笔记复制密文无法解密。
- [ ] 所有解密失败（密码错误、密文损坏、跨笔记移植、`kdf_params` 越界）在界面上完全一致。
- [ ] `kdf_params` 读取时做边界校验（`iter ∈ [100000,1000000]`、`keylen = 32`）。
- [ ] 加密笔记在数据库中 `content IS NULL` 且 `cipher IS NOT NULL`，由 CHECK 约束保证。
- [ ] 加密笔记的明文从未进入请求体以外的任何环节；主库与 WAL 中检索不到正文标记。
- [ ] 所有 `/api/*` 响应返回 `Cache-Control: no-store`，HTML 入口具备完整安全头与 CSP。
- [ ] 派生密钥、密码、解密正文只存在于当前页面内存；不写 Cookie、`localStorage`、`sessionStorage`、IndexedDB。
- [ ] 锁定清除密钥的同时清除内存草稿。
- [ ] 所有写请求（POST/PUT/DELETE）校验 Origin/Sec-Fetch-Site 与 CSRF Token；Host 白名单生效。
- [ ] 默认只监听 `127.0.0.1`，远程绑定需显式开关。
- [ ] 日志与错误页不含正文、密文、密码、助记问题、查询串、Cookie。
- [ ] `{@html}` 只出现在 `Markdown.svelte`，其输入必经 `DOMPurify.sanitize`；列表摘要与标题为纯文本插值。
- [ ] 加密笔记的正文与摘要不进入列表、搜索结果与任何 API 响应。
- [ ] 回收站里的笔记不出现在列表、搜索、分类计数与统计事件中；加密笔记的删除/彻底删除按钮在未解锁时不存在（前端门禁，服务端不校验密钥）；软删除期间正文/密文仍在库中的事实已在 8.4.5 与 FR-3.12 声明。
- [ ] 主密码接口只允许首次设置，重复提交返回 409；修改主密码走信息页，旧口令是否正确只由浏览器试解 GCM 认证标签判定，服务端没有任何口令验证能力。
- [ ] 改密只替换 `cipher` 与 `kdf_params`；`title/content/category_id/rev/updated_at` 与全局盐逐字不变。
- [ ] `GET /api/info` 只输出标准库运行时与配置值，不含正文、密码、密钥或令牌，且 `Cache-Control: no-store`。
- [ ] 关停令牌只存在于 `note.json`（`0600`），不进日志、响应、命令行与环境变量；`/api/shutdown` 仅在后台模式存在，CSRF 豁免只针对该路径。
- [ ] 前端构建产物通过 `go:embed` 进入二进制，运行时不依赖 Node/npm，无外部 CDN/字体/脚本。
- [ ] SPA 深链接刷新正常，`/api/*` 不会被回退为 HTML。
- [ ] 前端锁文件已提交，构建使用 `npm ci`。
- [ ] 数据库与数据目录权限符合 NFR-S10。
- [ ] 备份恢复演练通过，加密笔记仍可解锁；非浏览器客户端可用同一主密码解密同一笔记。
- [ ] 依赖安全扫描与版本更新检查完成。
