# 前端视觉评审与美化建议

> 版本基线：`v1.4.0`（git `55ab657`，2026-11-23）
> 评审方式：通读 `web/src` 全部视图与 `app.css`（1844 行设计 token + 组件样式），并在**临时沙箱库**（不含任何真实笔记数据）里用真实构建渲染、逐页截图核对。截图共 19 张，见 `docs/design/screens/`（文件名 `序号-页面[-主题|-设备].png`，视口 1440×900 桌面 / 375×812 移动，覆盖亮/暗/护眼三主题与引导、首页、列表、搜索、详情、编辑器、加密解锁、回收站、信息页、404）。
>
> 结论先行：**这套界面的底子是好的**——设计 token 完整、三主题机制成熟、可访问性细节（focus-visible、44px 触控目标、16px 移动输入字号、对比度）几乎无可挑剔，且没有模板装饰味。它的问题不在「丑」，而在**「单调 + 缺个性 + 状态不全」**：全站所有块面都是「1px 灰边 + surface 底 + 12px 圆角」的同一种卡片，唯一的色彩是蓝色强调色（和 GitHub 同款绿的热力图），衬线展示字体这个最大的个性资产用得极少。以下是基于证据的拆解与三条美化方向，以及分级落地清单。

## 2. 守住这些（做得好的，美化时绝不能丢）

1. **三主题机制本身是个资产**，尤其是「护眼」——米绿纸色在整个项目里是最有个人气质的元素。别在改版里把它弄丢或降级成普通绿。
2. **可访问性底子扎实**：全站 `:focus-visible` 有可见焦点环、移动端 44px 触控目标、iOS 16px 输入字号防缩放、`.sr-only` 标签齐全、正文对比度达标。
3. **信息架构干净**：存储与展示分离（UTC 存储、本地时区展示）、明文/密文的分级展示（`已加密` 徽标、解锁卡片）在 UI 上表达得清晰。
4. **无模板装饰**：没有渐变紫、emoji 图标、全大写小标签、01/02/03 编号这类「AI 味」——这个底子要保。
5. **引导页的克制**：居中、一行字、一个输入框，整屏只做一件事，是全站气质最好的页面之一。
6. **搜索命中高亮用强调色实底 `<mark>`**：亮/暗/护眼三主题下都清晰，是处理得对的细节。

## 3. 问题清单（按伤害程度排序，每条都对应具体类名）

### 3.1 全站块面同质：灰边灰卡铺满

`.card` / `.note-row` / `.detail-body` / `.cat-tree` / `.merge-bar` / `.ai-result` / `.search-results` 全部是「`1px solid var(--border)` + `var(--surface)` + `12px` 圆角」。宽屏 1280px 下看列表页，视觉上是一整片相似的灰盒子，**主次靠不住**——没法一眼区分「可点的行」「容器」「结果面板」。
**方向**：让「纸面」与「容器」分层——内容直接坐在底色上，容器用极浅阴影或干脆去掉边框，让边框只在分组处出现。

### 3.2 强调色身兼数职，全站只有一种色彩

品牌图标、链接、主按钮、焦点环、搜索高亮、事件占比条、激活分类、进度——全是 `var(--accent)`。色彩没有分工（对比 App 范式第 5 条：彩色在全站只干一件事吗？）。分类（产品里最该有颜色的实体）反而没有任何颜色。
**方向**：给「分类」引入一组色相（纯装饰的小圆点/色条），把 accent 收回为「该点这里 + 链接 + 焦点」。

### 3.3 衬线展示字体几乎没出场

`--font-display`（思源宋体/Songti）只用在品牌名、部分 `h1`、列表标题、Markdown 标题上，且字号克制（`h1` 最大 `2.2rem`、列表标题 `1.05rem`）。「你好，阿明。」是一行小号衬线；首页的日期说明是一行 0.95rem 灰字。**这个字体是全站最有个性的资产，却用得像点缀**。
**方向**：让衬线在品牌、页标题、日期这些「署名位置」放大、给足呼吸，形成记忆点；正文仍走黑体。

### 3.4 首页没有「页面感」，是一串等重的块

搜索框 → 速记卡 → 热力图 → 账簿，从上到下全部 16px 间距、同宽、同权重，宽屏右侧大片留白。这是 1280px 下最浪费的一屏。
**方向**：宽屏改两栏仪表盘（搜索+速记 | 热力图+账簿），窄屏回落单列；给「问候 + 今日」一个更像开场的处理。

### 3.5 状态不完整：加载是文字、空态是灰字

- 列表/详情加载：「笔记载入中…」「载入中…」——没有骨架屏。
- 空列表 / 空搜索 / 空回收站 / 404：一段居中灰字，没有行动指引，回收站空态甚至没有「返回全部笔记」之外的出口。
  **方向**：轻量骨架屏（几行占位条 + 呼吸动画）；空态给一句人话 + 一个主按钮；404 给回家的路。

### 3.6 动效几乎只有入场

除了热力图入场和 toast，列表展开（`.note-detail` 行内展开）、分类树展开/收起、搜索结果显示都是「瞬间出现」。
**方向**：给行内展开 150–200ms 的展开/收起过渡；行 hover 给极轻的底色或位移；不做每个区块 fade-up。

### 3.7 列表行的「删除」是全尺寸按钮

每行一个描边大按钮（桌面 40px 高），7 行笔记就是 7 个大灰钮，视觉噪音不小。触控设备上又必须够大（44px）——矛盾点是「按钮样式」而不是「目标尺寸」。
**方向**：桌面用文字级危险操作（hover 才显红），触控仍保留大目标；或把删除收进行尾图标。

### 3.8 顶栏功能齐全但平

品牌 + 4 个导航链接 + 用户名 + 锁定 + 主题循环钮挤在一行，当前路由没有 active 态，导航链接 hover 才有下划线。移动端 4 个链接靠横向滚动。
**方向**：给当前路由一个明确的 active 态；品牌位做成更有识别度的「本子」符号；用户名/锁定/主题的关系重新分组。

### 3.9 热力图是 GitHub 同款绿

亮/暗主题的四个色阶就是 GitHub contribution 色板。热力图是首页最大的视觉块，也是最像「别人家」的一块。
**方向**：三主题各配一套与自身纸色/墨色同族的色阶（护眼已是绿系，可自然延伸；亮/暗改到 accent 家族或暖墨阶）。

### 3.10 编辑器的「产品感」没做足

编辑页是全站最复杂、最值得打磨的一屏：左写右览两栏、模板/AI/模型药丸工具条、AI 结果面板。现在工具条药丸和主按钮都是描边/实底同款 8px 圆角，AI 结果区和正文框长得一样（都是 surface 卡），「结果只是建议」的身份感靠文字表达。
**方向**：AI 结果面板用强调色左边条（像详情页 `.hint` 那样）声明「这是建议」；两栏比例 1:1 改 5:7 让预览更宽；工具条 hover 态更明确。

## 4. 三个方向提案（先选气质，再动工）

以下三个方向差异在「气质」，共同点是不破坏第 2 节的好底子。选定后，按 huashu-design 的三方向门出真实初稿（每个方向 1 个完整可点 HTML + 截图）再定稿，不会直接改代码。

### 方向 A · 纸与墨（文学手账）

- **母题**：一本只属于你的纸质笔记本——墨色、纸的肌理、页边留白。
- **气质**：安静、私密、慢。衬线当家。
- **配色**：以护眼米绿纸为原型扩展出三档「纸」——白纸（微暖 `#fbfaf7`）、深墨纸（暖黑 `#1a1a17`）、米绿纸（现护眼）；强调色墨绿/黛蓝，危险色朱砂。热力图换墨绿阶。
- **字体**：标题/品牌/日期全走 `--font-display` 并放大字重差；正文黑体不变；时间继续等宽。
- **组件**：卡片从「灰底灰框」改为「纸面 + 极浅阴影 + 细页线」；列表行像索引卡；分隔多用虚线页线。
- **风险**：衬线过量显老气——守住「衬线只给署名位置，正文走黑体」。
- **试水页**：引导页、首页、列表页。

### 方向 B · 精密工作台（克制工具）

- **母题**：一把刻度精准的尺——信息密度高，但每一处都有秩序。
- **气质**：克制、专业、快。延续现有开发者工具基因，把「可用」做到「精确」。
- **配色**：亮/暗保留中性（Primer 微调、去灰），强调色收缩为「该点这里 + 链接 + 焦点」专职；加密/删除/合并给最小一组语义色。
- **字体**：正文黑体 + 衬线只留给品牌与详情标题；统计数字 `tabular-nums` 贯穿。
- **组件**：标题/摘要/时间三行明确分区；空态/骨架/加载补齐；行内展开做过渡；顶栏加 active 态。
- **风险**：容易「看起来没变」——成效全在状态与细节，必须逐页验收。
- **试水页**：列表页（层级、行内展开）、编辑器（两栏密度）。

### 方向 C · 活力手账（彩色但克制）

- **母题**：分类是你的颜色——像便利贴墙，彩色只干「分类」这一件事。
- **气质**：明亮、个人、有生气，秩序仍在。
- **配色**：中性底（亮色为主），为分类引入 5–6 个色相的圆点/角标（纯装饰、数据真实）；热力图用同族彩色阶；强调色不变。
- **字体**：同现状，标题衬线可留可去。
- **组件**：分类树彩色圆点、列表分类 chip 色点、空态用线条插画（SVG，非 emoji）、品牌活泼化。
- **风险**：最易滑向模板装饰（彩卡、渐变、emoji）——必须守住「彩色只干一件事」+ 留白。
- **试水页**：列表页分类树、首页热力图。

> 个人倾向：**A 或 A+B 的混合**最契合产品气质（「这本笔记只属于你」+ 护眼纸色已经是品牌雏形），且改动点集中在 token 层和首页/列表两页，风险可控。C 适合想先让界面「亮起来」的情况。

## 5. 落地路线图（分级，每项可独立验收）

### P0 · 快赢（不动布局，低风险，token/组件级）

1. 列表行「删除」弱化为文字级操作（桌面），保留触控大目标——`.note-row > .button` → `.linklike` + 危险色 hover。
2. 按钮交互补齐：主按钮 hover 从 `opacity` 改为亮/位移/阴影，加 `:active`；`.button-quiet` hover 加轻 surface。
3. 空状态升级：`.empty-hint`（列表/搜索/回收站）与 404 加 SVG 线条图形 + 一句人话 + 主按钮；回收站空态补「返回全部笔记」。
4. 加载骨架：列表 `.note-rows` 与详情 `.detail-body` 用占位条骨架替换「载入中…」文本。
5. 热力图色阶按主题重配（亮/暗不再用 GitHub 绿，改 accent/墨绿家族），图例随动。
6. 行内展开 `.note-detail` 与分类树加 150–200ms 过渡；`prefers-reduced-motion` 全关（现有模式已具备，沿用）。
7. 分类引入彩色圆点（`CategoryTree` / 列表 `.note-meta` 的分类名旁），纯装饰、色板固定 6 色、暗色下提亮。

### P1 · 中期（涉及结构与测试，需要配套更新 `*View.test.ts`）

8. 首页宽屏两栏仪表盘：`HomeView` 结构改为 `grid`（`search+quick | heat+ledger`），≤1024px 回落单列（复用现有断点）。
9. 顶栏：导航加当前路由 `data-active` 态；品牌图标精细化为「本子/钢笔」符号（SVG 已在 `Layout.svelte`，重绘 + 品牌色）。
10. 三主题升格为「同一品牌的三种纸」：三套 `data-theme` 共用强调色家族（墨绿/黛蓝），亮=白纸、暗=深墨、护眼=米绿纸；`.card` 去大面积灰底改纸面 + 极浅阴影。
11. 详情页标题区：标题放大、meta 重组（日期/分类色点/加密徽标/复制按钮分区更清楚）。
12. 编辑器：两栏 1:1 → 5:7；AI 结果面板加强调色左边条（复用 `.hint` 语言）；工具条药丸 hover 态。

### P2 · 大改（选定方向后按三方向门做）

13. 按第 4 节选定方向重写 token 层（`app.css` 前三段）与各视图标记，逐页验收亮/暗/护眼 + 1440/375 两档。
14. 品牌资产：favicon（现 `web/public/favicon.svg` 650 字节）+ `document.title` 前缀的视觉一致性。

## 6. 约束清单（改前端时不可破坏的硬规则）

来自 `AGENTS.md` 与代码现状，改视觉时逐条对照：

- **安全不变量**：`{@html}` 只允许出现在 `web/src/components/Markdown.svelte`，且输入必须先过 `renderMarkdown` → `DOMPurify.sanitize`（搜索命中再经 `highlightRendered` 只追加 `<mark>`）。美化不得引入新的 `{@html}` 或绕过净化。解密与含正文响应 `Cache-Control: no-store`，不要在样式/脚本里缓存正文。
- **主题机制**：`data-theme`（light/dark/eye-care）由 `lib/theme.ts` 写入 `<html>`，localStorage `note.theme`；新配色必须三套齐全，`color-scheme` 与 `--accent-contrast` 同步。
- **可访问性下限**：正文 ≥14px（移动 16px）、可点元素 ≥44×44（触控）、正文对比度 ≥4.5:1、`:focus-visible` 焦点环、iOS 16px 输入字号防缩放——现 CSS 已保证，改版不得破坏。
- **可点元素与真实交互**：导航、tab、展开、表单状态做出来且控制台零报错；`prefers-reduced-motion` 分支保留。
- **技术约束**：Svelte 5 runes（`$state`/`$derived`/`$effect`）、无 UI 组件库、无 CSS 框架、无状态管理库；样式仍集中在 `app.css` + 组件 `<style>`，不要引入 CSS-in-JS。
- **测试配套**：`HomeView.test.ts` / `NoteListView.test.ts` / `InfoView.test.ts` / `ThemeSwitch.test.ts` 等按标记断言（如 `data-merge`、分类树回调、主题循环），改结构时同步更新；改动合入前 `just test` 与 `just check` 全绿。
- **展示口径**：所有时间展示仍走 `lib/time.ts#formatLocalStamp`（本机时区 `2006-01-02 15:04:05`），样式可改、口径不能动；自动标题（速记/合并）仍是本地时间格式，别改成别的样子。
- **数据诚实**：不编造统计数据、评价、logo 墙；分类彩色圆点是纯装饰，不伪造计数。
